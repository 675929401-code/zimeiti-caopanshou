# 自媒体操盘手 · 部署闭环固定口径

更新时间：2026-09-01
适用事实源：`F:\总项目文件\Skill存储系统\01_网页开发项目\自媒体操盘手\当前版本`

本文档只解决一个问题：以后本地改完代码，怎样稳定、快速、可追溯地进入 Git 仓库和服务器，避免“打补丁式部署”“半新半旧”“素材错位”“模型接口慢或阻塞”。

## 1. 固定结论

默认采用：

```text
代码局部更新，线上整版发布。
Git 记录完整源码快照，服务器运行完整 release。
会员数据、钱包数据、用户上传素材、生成历史、服务器密钥永远不随代码覆盖。
```

这不是把所有东西重刷一遍，而是把“程序版本”一次性发布完整，避免服务器出现部分文件新、部分文件旧、构建产物和源码不一致。

## 2. 四条链路必须分开

| 链路 | 存放位置 | 发布方式 | 是否允许部署覆盖 |
| --- | --- | --- | --- |
| 源代码、配置模板、测试、迁移脚本 | 本地当前版本 + Git 发布仓 | 验证后提交 Git，再构建完整 release | 允许覆盖应用代码 |
| 数据库表、RPC、索引、权限 | `supabase/migrations` + 生产数据库 | 先备份，再执行 forward-only 迁移 | 禁止用代码包覆盖 |
| 会员、积分、现金、订单、会话、生成历史 | 生产数据库 | 只通过业务接口或迁移演进 | 禁止覆盖 |
| 用户上传素材、后台上传素材、生成图片/视频 | `shared/uploads` / COS / CDN / 数据库元数据 | 独立存储、独立备份、按 URL/key 引用 | 禁止随代码覆盖 |

## 3. 发布模式

| 模式 | 使用场景 | Git 怎么做 | 服务器怎么做 | 数据怎么做 |
| --- | --- | --- | --- | --- |
| `DOCS/TOOLING` | 部署手册、验收脚本、只影响操作员的工具链 | 提交并推送，保证仓库有最新标准 | 默认不切换线上业务 release；只有服务器也需要该工具时才发布 | 不动数据库和素材 |
| `CODE-PATCH` | 页面、导航、聊天流式、接口小修 | 提交局部代码 diff，但 Git 留完整快照 | 构建完整 release 并切换 | 不动数据库和素材 |
| `CONFIG-ONLY` | 提示词、Skill 覆盖、Banner、示例配置 | 不改代码或只改配置模板 | 通常不重启应用 | 后台/数据库保存并发布 |
| `ASSET-PUBLIC` | 官方演示图、模型图标、示例封面 | 受控 public 素材进入 manifest | 随完整 release 发布 | 不影响用户上传素材 |
| `DB-MIGRATION` | 新表、新 RPC、字段变更 | 只提交 migration SQL | 应用发布前后按计划执行 | 先备份，再迁移 |
| `FULL-RELEASE` | 漫剧工作台、模型网关、后台治理这类跨域大改 | 完整源码快照 + 迁移 + 文档 | 候选 release 全量构建、健康检查通过后切换 | 数据只迁移，不覆盖 |

如果不确定，默认选 `CODE-PATCH + 完整 release`，不要在服务器上手工替换几个文件。

## 4. 标准执行顺序

```text
本地当前版本修改
  → TypeScript / 专项脚本 / 浏览器端到端验证
  → deploy:standard:verify 检查代码、数据、素材、密钥边界
  → 在当前 Git 工作区提交
  → 推送精确 commit 到 origin
  → 服务器创建候选 release
  → 候选端口检查：首页、核心页面、模型接口、SSE 流式、素材
  → 通过后切换 PM2/Nginx 当前版本
  → 公网域名再次验证
  → 记录 commit、Build ID、release 路径和验收报告
```

禁止把“页面 200”“能打开首页”“Git push 成功”单独当成上线成功。

### 5.1 固定 5000 端口的最新源码门禁

本地生产预览不再允许“standalone 启动失败后静默回退到另一个旧 `next start`”。固定流程是：

```text
计算当前 Git 已跟踪文件 + 未忽略新文件 + 本地环境文件的 SHA-256 指纹
  → 完成 Next.js production build
  → 再次计算指纹，构建期间源码发生变化则作废
  → 将源码指纹、fileCount 与 BUILD_ID 写入 .next/local-source-fingerprint.v1.json
  → 启动前重新核对源码指纹 + BUILD_ID
  → 任一不一致直接拒绝占用 5000，要求重新构建
```

固定执行入口：

- 一键最新生产预览：`pnpm preview:latest`（先构建当前源码，再启动）；
- 构建：`scripts/run-build.mjs`；
- 启动：`scripts/run-start.mjs`；
- 门禁算法：`scripts/local-build-fingerprint.mjs`；
- 回归验证：`scripts/verify-local-build-fingerprint.mjs`。

运行目录 `.runtime/`、`.next/`、测试证据、备份快照不属于构建输入；业务源码、配置模板、新增未跟踪源码和本地环境值变化都必须让旧构建失效。环境文件只参与不可逆摘要，不写入回执内容。

构建结束还必须满足：

- `.next/standalone` 内不存在 `.env`、`.env.*`、`.npmrc`、`.secure`、私钥、Token、Cookie 或 credential 文件；
- 磁盘 `.next/BUILD_ID`、指纹回执 `buildId`、`/api/version` 的 HTTP `buildId` 三者一致；
- 5000 的监听进程命令行指向当前事实源的 `.next/standalone/server.js`；
- 旧构建只可作为可恢复快照，不可由守护进程自动复活；
- 最新源码构建失败时保持端口关闭或回滚到明确批准的稳定 release，禁止假装“最新版已运行”。

## 6. 服务器覆盖的边界

允许覆盖：

- 应用源码；
- `.next/standalone` 等构建产物；
- 受控 `public/` 官方示例素材；
- 发布脚本和部署模板。

禁止覆盖：

- `.env.local`、`.env.production`、`.npmrc`；
- `shared/data`；
- `shared/uploads`；
- `shared/assets/current` 和历史 `shared/assets/releases`；
- `shared/runtime`；
- `shared/logs`；
- `shared/backups`；
- 生产数据库；
- 会员、积分、现金、订单、生成历史。

所以用户口中的“直接覆盖服务器”在本项目中只能解释为：

```text
直接覆盖应用程序版本，不覆盖持久化数据。
```

## 7. 模型响应和流式输出门禁

每次涉及聊天、模型路由、对话 UI、代理网关、Nginx/PM2 的发布，都必须验证：

- `/api/chat-models` 返回 200 且模型列表非空；
- `/api/llm` 返回 `text/event-stream`；
- 首个可见 token 不是等整段生成后才出现；
- 前端消息不会因为历史会话刷新而丢失；
- 浏览器端没有 5xx、未捕获错误或关键资源失败；
- Nginx / 代理层不缓存 SSE；
- 运行时环境由 Node/dotenv 加载，禁止 shell `source .env.local`。

这条是为了防止再次出现“本地不卡、线上卡”“打字机效果消失”“聊天看起来被阻塞”。

## 8. Git 仓库角色

| 远端 | 当前/目标职责 | 说明 |
| --- | --- | --- |
| `origin` | 当前可作为服务器发布裸仓；长期目标是正式私有主仓 | 记录本阶段可部署 commit |
| `backup` | 当前有本机归档；长期目标是异地私有备份仓 | 不能把本机归档当灾备终点 |
| `server-bare` | 服务器受控发布仓 | 可用于服务器拉取精确 commit |
| `legacy-gitee` | 旧历史仓兼容/冻结 | 不作为新生产主仓 |

长期最好升级为“正式私有主仓 + 异地私有备份仓 + 服务器只拉取已验证 commit”。但当前阶段，只要候选 release、健康检查、SSE、素材、模型和公网验证都通过，可以继续采用服务器裸仓发布，不要把它误称为异地灾备。

## 9. 素材存储选择

短期：服务器硬盘/挂载目录适合放当前已受控的官方演示素材、头像、缩略图和少量运行缓存。

长期：用户上传素材、生成图片、视频、参考图、素材市场内容，建议迁到 COS/OSS/S3 + CDN。

理由：

- 图片/视频越来越多时，服务器带宽会成为瓶颈；
- CDN 能明显改善瀑布流、头像、素材库加载速度；
- 部署代码不会误删用户资产；
- 可以做对象版本、跨区备份、生命周期清理；
- 数据库只保存 key、checksum、owner、用途、状态和访问权限。

执行顺序不要颠倒：先保证现有硬盘链路正确，再做 COS/CDN 迁移。不要在热修复中同时改存储体系和业务逻辑。

## 10. 一句话执行准则

以后只认这个闭环：

```text
本地源码是事实源；Git 是版本证据；服务器 release 是运行实体；数据库和素材是持久资产。
代码可以整版覆盖，数据和素材绝不跟着覆盖。
```
