# 模型接入激活门（2026-08-22）

## 目标

管理员新建的视频、生图或文案模型一律以 `is_active=false`、`is_hidden=true` 落库。普通新增/编辑接口不能把隔离模型直接启用或解隐藏；发布必须经过独立的服务端验收激活通道。

本门禁只约束部署本版本后新建、带有隔离标记的记录。没有隔离标记的既有模型保持原状态和原管理行为，不做批量隐藏，不追溯停用。

## 五项强制证据

新视频模型发布前必须同时存在以下服务端生成并已持久化的证据：

1. `secret_resolution`：服务端成功解析密钥引用，证据不得包含密钥内容。
2. `endpoint_connectivity`：目标端点及认证后的模型映射可达。
3. `protocol_fixture`：协议请求、状态映射和结果字段 fixture 通过。
4. `canary`：真实最小生成达到成功终态。禁止用 mock、只读探测、任务已受理或人工豁免替代。
5. `result_persistence`：canary 结果已转存至平台持久存储，并能由平台稳定读取。

证据绑定模型 ID、模型名、provider、协议、端点、密钥引用及协议配置的 SHA-256。任一绑定字段改变都会使旧证据失效；已发布模型必须先隐藏、停用，再重新验收。

## 现有字段下的实现

### 视频模型

`video_models.api_protocol_config.__model_activation_gate` 保存隔离标记与验收证据，schema 为：

- `media_model_activation_gate.v1`
- `media_model_acceptance_evidence.v1`

普通管理员接口会删除客户端提交的保留 gate 字段，并保留数据库中已有的服务端 gate，因此客户端不能伪造或覆盖验收证据。服务端验收器可调用 `issueVideoModelAcceptanceEvidence` 和 `persistVideoModelAcceptanceEvidence` 生成、绑定并持久化证据。

`POST /api/admin/models/activate` 只接收 `id` 和 `model_type`，不接收证据正文。它重新读取数据库中的模型和证据，五项检查齐全且绑定哈希一致后，才以 `inactive + hidden` 条件更新为 `active + visible`。

### 生图模型

当前 `cover_models` 没有 JSON/备注类的服务端专用证据字段。在不改数据库 schema 的约束下，不能安全保存通用验收证据。因此：

- 新记录使用 `pending-cover-model-` ID 前缀；
- 新记录强制停用、隐藏；
- 普通 PUT 不能启用或解隐藏；
- 通用激活接口返回 `IMAGE_ACCEPTANCE_EVIDENCE_STORE_UNAVAILABLE`。

AutoDL H3 的既有固定图/视频模型仍只允许通过已存在的 `activate_autodl_h3_selfhost_models_v1` 原子 RPC 和固定验收档案成对激活，不由普通管理员 PUT 解锁。

### 文案模型

当前 `llm_models` 同样没有适合保存通用验收证据的 JSON 字段。新记录以 `user_access=pending_model_activation` 标记，并强制停用、隐藏；普通 PUT 不能移除标记或发布。通用激活接口返回 `TEXT_ACCEPTANCE_EVIDENCE_STORE_UNAVAILABLE`。

后续若新增专用证据表或 JSON 字段，应迁移为与视频相同的服务端证据方案；在此之前保持 fail-closed。

## 接线路由

- `POST /api/admin/models`：三类新模型统一隔离。
- `PUT /api/admin/models`：隔离模型禁止普通启用/解隐藏；视频保留服务端 gate。
- `POST/PUT /api/admin/video-models`：兼容旧入口，同样执行隔离和普通编辑门禁。
- `POST /api/admin/cover-models`、`PUT /api/admin/cover-models/[id]`：兼容旧生图入口并保持 fail-closed。
- `POST /api/admin/video-test`：只记录只读检查或提交受理结果，不再自动解隐藏。
- `POST /api/admin/models/activate`：唯一通用验收激活入口；当前只有证据可安全持久化的视频模型可通过。

## 明确不等价

- `GET /v1/models` 成功不等于真实生成成功。
- 真实任务返回 `task_id` 不等于达到成功终态。
- mock/fixture 通过不等于 canary 通过。
- canary 生成成功但未转存，不等于结果可持久化。
- 管理员勾选“启用”不构成验收证据。
- 不提供 canary 豁免。

## 零网络回归

```powershell
pnpm exec tsx scripts/verify-model-activation-gate.ts
```

该脚本覆盖新模型默认隔离、旧模型不追溯、客户端 gate 伪造被剥离、五项证据与绑定哈希、canary 不可豁免、普通 PUT 旁路阻断、独立激活 compare-and-set，以及旧视频测试接口不再自动解隐藏。脚本禁止网络调用且不访问数据库。
