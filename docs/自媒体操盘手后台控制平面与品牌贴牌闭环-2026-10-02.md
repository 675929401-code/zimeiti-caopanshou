# 自媒体操盘手后台控制平面与品牌贴牌闭环

日期：2026-10-02  
范围：F 盘当前版本，本地产品控制面；不代表服务器或生产环境已经更新。

## 产品判断

当前后台已经具备真实会员、钱包、收益快照、公告回执、权限、二次验证、任务记录、对象存储和飞行日志等基础能力，但还不能称为行业标杆。主要问题不是缺少页面，而是各页面对同一业务使用不同状态和口径，异常时还会把“不可用”显示成 `0`。目标是把后台升级为一套可追溯的控制平面：每项设置有事实源、发布版本、实时状态、操作权限、审计回执、失败恢复和下钻入口。

## 品牌名称与标志

2026-10-02 用户明确暂停平台名称、Logo 和封面视觉设计。本阶段保留现有“自媒体操盘手”名称，只建设图片上传、草稿、发布、回滚和全站消费等功能链路；任何候选名称或候选图均不得自动写入正式品牌配置。

## 后台一级导航

1. **平台指挥中心**：总览、用户经营、资金收益、任务交付、模型供应商、安全态势、运维恢复。
2. **会员与经营**：会员档案、邀请关系、权益套餐、试用、卡密、线下收款、账单和对账。
3. **消息与触达**：活动管理、事务消息、受众、投递队列、回执、展示策略和模板。
4. **智能体与模型**：智能体、提示词版本、模型资源池、工作台绑定、渠道验收和成本策略。
5. **品牌与站点**：品牌资产、主题、页面布局、域名、站点、邮件身份和贴牌发布。
6. **安全中心**：风险态势、案件、账号与会话、密钥与渠道、管理员权限和处置记录。
7. **系统运维**：健康、飞行记录、事故、备份、恢复演练、同步、版本和发布标记。
8. **权限与审计**：管理员授权、二次验证、敏感操作、配置变更和不可变审计。

一级导航按经营对象组织，二级导航按任务组织。相同事实只保留一个权威入口，例如“账号到账通知”不再同时由会员页、公告页和弹窗页各自定义一份。

## 品牌与基本设置闭环

基本设置拆为四块：

### 品牌与站点

- 正式名称、简称、产品线、品牌句、欢迎语。
- 方形标志、横版标志、明暗版、favicon、分享图、登录背景。
- 图片直接上传到平台自有对象存储，数据库保存稳定资产 ID、对象 key、SHA-256、MIME、宽高、字节数和上传人。
- 草稿保存不影响用户；发布后才切换全站；发布版本不可变，可原子回滚。
- 登录、主站壳层、页面标题、favicon、邮件和分享卡片读取同一已发布修订。

生产环境不把上传文件保存在 Next.js 发布目录。服务器换版、扩容或容器重建会使本机文件失效；应保存在腾讯 COS、Supabase Storage 等平台自有对象存储，通过同源资产接口读取。

### AI 策略

- 全局系统前缀、自动头像策略、默认风格和模型。
- 自动生成必须有耐久任务状态、费用状态、失败原因和人工重试。
- 页面描述必须与实际提示词一致，不允许界面写“赛博朋克”而真实提示词明确禁止该风格。

### 安全与恢复

- 平台管理密码、管理员二次验证、恢复包状态、最近演练和可恢复时间点。
- 已永久停用的浏览器恢复令牌不再出现在基本设置。
- 恢复动作只在系统运维中执行，必须有备份身份、校验和、影响预览、操作者和结果回执。

### 站点与域名

- 官方域名、客户域名、DNS 所有权、TLS、最近探测、证书到期时间和发布版本。
- 未验证域名、证书未生效或 HTTPS 探测失败时禁止发布。

## 贴牌完整链路

目标对象：`tenant → site → domain → brand revision → published site`。

1. 创建租户和站点，绑定管理员成员关系。
2. 输入客户域名并规范化为 ASCII/IDN，生成唯一 TXT 验证令牌。
3. 客户配置 TXT 所有权记录和 CNAME 业务记录。
4. 服务端定时解析 DNS；同一域名只能归属一个租户。
5. 所有权通过后调用网关或 Cloudflare for SaaS 创建 custom hostname。
6. 分开记录 hostname、SSL certificate 和 DNS routing 状态；三项都通过后进入“可预览”。
7. 管理员在预览域名检查品牌、登录、会员、公告、账单和资产隔离。
8. 发布时原子切换 `published_revision_id`；失败保留上一版本。
9. 请求仅根据可信 `Host` 查找站点；未知 Host 直接拒绝，不能回退到其他客户。
10. 域名、品牌、会员、消息、订单、资产、权限和审计全部携带 `tenant_id/site_id`。
11. 证书到期、DNS 漂移或探测失败进入异常状态并告警；恢复后重新验证。
12. 回滚只切换到上一已发布品牌修订，不重写历史内容。

状态机：

```text
待配置 → 待验证 → DNS已验证 → TLS签发中 → 可预览 → 已发布
                                           ↘ 异常/暂停 ↗
```

多域名同品牌与真正多租户贴牌必须分开。用户注册域名并拥有独立会员、公告、账单和品牌，属于真正多租户，需要核心业务表和会话令牌都有租户边界。

## 公告、会员推送与弹窗闭环

当前系统公告、账号通知、试用弹窗和视频横幅来自四套数据。目标统一为：

```text
业务事务/运营活动
→ outbox
→ campaign run
→ per-user delivery
→ 拉取
→ 展示
→ 阅读/点击/关闭
→ 失败重试或死信
→ 管理端回执
```

建议表：

- `message_campaigns`：内容、受众规则、版本、计划时间、过期时间和展示策略。
- `message_campaign_runs`：每次发布或重推的不可变内容和受众快照。
- `message_deliveries`：每用户、每版本、每渠道的投递状态。
- `message_events`：展示、阅读、点击和关闭的追加事件。
- `message_outbox`：会员、钱包、安全等业务事务内写入的可靠出口。
- `message_surface_policies`：modal、toast、消息中心和场景横幅的优先级规则。

统一优先级：

```text
P0 强制退出/严重安全
P1 会员开通/钱包到账/待操作凭证
P2 需要确认的紧急系统公告
P3 普通系统公告
P4 试用和运营引导
```

同一时刻只能出现一个 modal，其余进入可见队列。普通公告默认进入 toast 和统一消息中心；只有 P0、P1 或明确 `require_ack` 的 P2 才能阻断。铃铛打开统一列表，按全部、待处理、系统、账号资产、安全筛选。

“目标人数”不能写成“已送达”。管理端分别显示 queued、fetched、impression、read、actioned、failed、dead_letter、suppressed，并在统计接口失败时显示“不可用”。

## 平台指挥中心

每个指标都使用同一合同：

```text
value
definition
source
asOf
freshnessSeconds
coverageRatio
partial
status
drilldownUrl
```

### 总览

- 当前 P0/P1 事故、关键服务、源码/构建/运行身份。
- 今日用户、实际收款、使用收入、供应商成本、毛利和任务成功率。
- 数据新鲜度、缺失源和部分覆盖状态。

### 用户与经营

- 注册、验证、首次使用、活跃、首充、正式会员、流失。
- DAU/WAU/MAU、7/30 日留存和注册到付费漏斗。
- 按来源、套餐、智能体和租户下钻。

### 资金与收益

- 实际收款：支付订单和线下收款事实。
- 使用收入：任务创建时的售价快照。
- 供应商成本和任务级毛利。
- 待入账、账实不符、负余额、缺少收益快照。

实际收款、使用收入和钱包余额是三个不同指标，禁止互相推算后使用同一个“收入”名称。

### 任务与交付

- submitted、queued、running、unknown、failed、succeeded、delivered。
- 各业务和模型的成功率、P50/P95、积压和卡死。
- “已扣款无交付”“已交付无收益记录”“成功无资产”等一致性异常。

### 模型与供应商

- 目录可见、凭据配置、最近真实验收、最后成功/失败、熔断和恢复资格。
- 供应商余额只在有受支持的只读接口时展示，否则明确为“未知/未接入”。

### 安全态势

- 开放严重案件、登录失败、限流、注入、提示词套取、后台拒绝和二次解锁失败。
- 风险账号、IP、设备和 Trace 聚类。

### 运维与恢复

- 延迟、流量、错误、饱和度四个基础信号。
- 数据库、对象存储、队列、依赖、构建版本和任务积压。
- 备份年龄、校验、异地回执、最近恢复演练、RPO/RTO。

更新节奏：关键事故和积压 5–15 秒；错误率、P95、安全聚合 1 分钟；用户经营、收入和成本 5 分钟；留存与容量每日；恢复演练和权限复核按月或季度。

## 安全中心闭环

安全中心按 Govern、Identify、Protect、Detect、Respond、Recover 六环组织：

```text
安全事件
→ 标准化、风险评分和指纹去重
→ 创建或合并案件
→ 告警
→ 管理员认领
→ Trace/登录/用户/会话/订单调查
→ 二次解锁后执行白名单处置
→ 自动验证
→ 解决或恢复
→ 审计和复盘
```

白名单处置包括撤销会话、暂停账号、禁用泄露密钥或故障通道、临时阻断明确恶意来源、标记误报。每次处置必须带权限、短时二次解锁、影响预览、原因、幂等键和验证结果。代码修改、数据库结构修改、批量余额修正、付费重放和生产部署不能由安全中心自动执行。

安全日志记录 when、where、who、what、结果和原因，通过 Trace ID 关联；密码、令牌、连接串、密钥、完整签名 URL 和支付敏感信息禁止进入日志。

## 系统运维闭环

```text
探针/指标
→ SLI/SLO
→ 多窗口错误预算告警
→ 事故去重
→ 认领
→ Trace/任务/订单/模型下钻
→ 安全恢复动作
→ 重新探测和业务一致性验证
→ 关闭事故
→ 根因与行动项
```

可自动执行的动作只限无费用、可逆、确定性的维护，例如重新跑只读探针、恢复无副作用轮询和暂停已确认故障的通道。付费任务不得自动重放。

## 实施顺序

| 阶段 | 交付 | 完成门槛 |
|---|---|---|
| P0-1 | 单站品牌中心、上传、草稿/发布/回滚、全站消费 | 重启后资产仍可读；登录/壳层/标题一致；审计和并发冲突可见 |
| P0-2 | 只读平台指挥中心 | 事实源一致；来源失败不归零；经营、任务、安全、运维可下钻 |
| P0-3 | 修复现有公告/账号/试用调度缺陷 | 确定优先级；无双弹窗；后台回执错误可见；写操作受权限和二次验证保护 |
| P0-4 | 安全案件与处置控制面 | 事件去重、认领、处置、验证、审计闭环 |
| P1-1 | 统一消息 outbox/delivery/event | 事务消息不丢不重；展示、阅读、失败和死信可核对 |
| P1-2 | 租户、站点、域名和品牌隔离 | 两域名并发无串租；DNS/TLS/HTTPS 实际通过；可原子回滚 |
| P1-3 | SLO、事故、备份和恢复演练 | 错误预算告警可行动；异地备份有校验；一次性环境恢复成功 |

所有阶段先做本地、零付费和桌面 Web 验收。数据库迁移、Git 推送、服务器发布、证书签发和正式域名切换分别保留独立回执，不能互相代替。
