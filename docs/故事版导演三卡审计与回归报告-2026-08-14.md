## 2. 旧版冲突与根因

1. 输入仍使用 `storyboard_segmented_copy` 等五个旧 ID，角色设定和特殊备注分成两个字段，不符合新的四字段合同。
2. 三张提示词都明确写着“不输出 JSON”，与未来自动导入的机器包要求直接冲突。
3. 输出依赖“第二个代码框”“固定顺序永远是”等位置规则。标题改名、增添说明或调整顺序就可能错绑。
4. `output_style={}`，数据库没有声明机器输出版本、导演模式和可导入字段。
5. 可见代码框同时承担人读和机器映射，导致格式越改越脆弱。
6. 旧版方法论较完整，但三类导演差异仅是一段附加策略，缺少机器可识别的 `director_mode`。
7. 旧版把4/5个故事板面板直接换算为4/5次切镜，并规定“每格”固定秒数；这会让约10秒视频被硬切得过密。面板应是视觉素材覆盖，实际镜头数必须另行按语义判断。

## 3. v6 方案

### 输入

稳定输入版本：`storyboard_director_input.v1`

- `segmented_script`
- `animation_style`
- `aspect_ratio`
- `special_notes`

协议层兼容旧五字段和常见中文标签；旧角色设定会合并进 `special_notes`，保存后使用新 ID。

### 输出

稳定输出版本：`storyboard_director_output.v1`

每段先输出独立的“生图 Prompt”标准 `text` 代码框，再输出独立的“图生视频 Prompt”标准 `text` 代码框。整批结果末尾另附 `json` 机器包。导入只读取：

- `schema_version`
- `artifact_type`
- `director_mode`
- `segments[].segment_id`
- `segments[].panel_count`
- `segments[].layout`
- `segments[].pacing_mode`
- `segments[].actual_shot_count`
- `segments[].panoramic_anchor_role`
- `segments[].storyboard_image_prompt`
- `segments[].image_to_video_prompt`

标题、解释文字和代码框顺序不再承担机器映射职责。

### 三种真实差异

- `high_energy`：强动势、夸张反应、动作触发的漫画化语义效果。
- `cinematic`：因果、空间连续、有动机运镜、光影和节奏。
- `lyrical`：微表演、关系距离、情绪递进和克制的语义母题。

三张卡共享资产锁定、4/5 格故事推导、语义可视化、医学友好展示、动作型视频 Prompt 和质量门。原 v6.0 精简替换方案已废弃；正式方案见 `docs/故事版导演三卡稳定协议-v6.1.md`。它保留完整导演核心，只精确替换7处错误的布局/节奏句和旧输出协议。

### 4–5格与实际镜头

- 四个有效视觉节拍或没有独立宽幅锚点：`panel_count=4`、`layout=two_by_two`。
- 只有存在独立高潮、结论、警示揭示、空间全貌或情绪收束：`panel_count=5`、`layout=four_plus_panorama`。
- 第5格为底部全宽锚点，禁止上2下3等宽和硬凑第五格。
- 面板数不等于切镜数；约10秒高能版2–4镜、电影版2–3镜、抒情版1–2镜。

## 4. 迁移与回滚

迁移：`scripts/migrations/20260814_storyboard_director_agents_v6_1.sql`  
回滚：`scripts/migrations/20260814_storyboard_director_agents_v6_1_rollback.sql`

迁移特性：

- 只更新三个已知 agent ID，不按模糊名称批量命中。
- 先备份名称、描述、提示词、预设、输出协议和上下文等可编辑配置。
- 不备份完整行，不读取或复制 API key、provider、proxy、用户、支付或计费数据。
- `ON CONFLICT DO NOTHING` 保留第一次执行前的回滚基线。
- 每张卡最终在数据库保存独立完整提示词，后台可继续编辑；现有核心区占当前提示词约91.7%，迁移只精确替换7处布局/节奏原句和旧固定输出尾段，没有硬编码到前端。
- 新提示词写入 `prompt_versions`，重复内容不会重复插入。

原 v6 迁移已经改成主动报错文件，禁止执行。v6.1 目前仅生成，未执行；当前环境没有数据库直连或事务 SQL RPC，不能用 REST 分步更新冒充原子迁移。
