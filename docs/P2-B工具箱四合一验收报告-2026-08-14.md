# P2-B 工具箱四合一验收报告

日期：2026-08-14

## 已落地

1. 主站顶部导航和侧栏将分段、文案提取、视频提取、文字排版收拢为一个“工具箱”入口，点击进入 `/tools`。
2. `/tools` 使用四项分段控制切换真实组件，不使用 iframe，也没有复制业务实现。
3. `/segmenter`、`/extract?tab=text`、`/extract?tab=video`、`/formatter` 保持 200 与独立可访问。
4. 桌面工作区统一为输入/结果双列；移动端 640px 以下切换为单列。
5. 分段时长、排版规则、文案纠正规则和视频平台信息集中到顶部；历史入口保留在工具栏。
6. 移除了嵌入空态内重复的时长/规则 chip；输入与结果列使用相同最小高度，主操作留在输入列底部。
7. 四标签使用 URL query、刷新持久化、方向键/Home/End 键切换和正确的 tab/tabpanel ARIA 关系。
8. 页面 CSS 只作用于 `/tools` 的 CSS Module，不使用 `!important`，未覆盖分镜工作台和后续全局主题。
9. 390px 下四个主标签等分完整显示，隐藏次级描述；输入标题/字数/粘贴使用两行网格，命令按钮保持 44px 触控高度且文字不折成单字列。
10. 提取子页不再把 AppContext 初始化中的空状态误判为登出。仅有合法 `auth_token` 时先调用 `/api/auth/me`，成功后恢复 `auth_user` 和全局认证；401/403 仍清理失效缓存并返回首页，网络错误提供重试。

## 无费用验证

- 全量 TypeScript：`tsc -p tsconfig.json --noEmit`，通过。
- 新增/核心工具目标 lint：通过。
- 契约脚本：`scripts/verify-toolbox-ui.ts`，12 项 fixture 契约通过。
- 路由：四个 `/tools?tab=` 路由及四个旧链接均返回 HTTP 200。
- 无费用认证 fixture：`/api/auth/dev-session` 获取的令牌调用 `/api/auth/me` 返回 HTTP 200 且含用户数据；伪造无效令牌返回 HTTP 401。守卫契约覆盖成功恢复、失效清理/返回首页、网络失败重试三条分支。
- 未调用付费模型、生成接口或支付接口。

## 已知边界

- “视频提取”复用当前真实的视频链接解析与下载链路；项目没有可复用的本地视频上传转写接口，因此页面没有虚构上传按钮。
- 提取页只恢复通过 `/api/auth/me` 验证的会话；未登录或令牌失效仍返回首页。该恢复逻辑只解决初始化竞态和缺失 `auth_user` 缓存，不代替服务端权限判断。
- 对共享导航文件执行扩大范围 lint 会命中其既有 React Compiler 与 `any` 基线；本轮新增/核心工具目标文件 lint 为 0 错误，全量 TypeScript 为 0 错误。
