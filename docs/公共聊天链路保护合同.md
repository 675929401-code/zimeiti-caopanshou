# 公共聊天链路保护合同

本合同落实用户本轮要求：错误原因清楚反馈，避免后续修改其他功能时误动公共聊天链路。业务权限仍服从根 AGENTS.md。本合同的唯一保护清单为 `.engineering/chat-reliability-lock.v1.json`；校验入口为 `scripts/verify-chat-reliability-lock.mjs`。

## 受保护行为

- 站内积分与模型中转账户余额分别按明确错误码反馈；单独 HTTP 402 或“余额不足”字样不能证明站内积分不足。上游计费状态不明时明确说明需管理员核对。
- 已提交但终态未知，保留原请求与已有内容；不得自动重发、切换模型重放、强行标为成功/失败，或承诺未扣费。未知结果不回填成“未发送”的草稿，不恢复旧改写状态，也不提供重新生成或继续生成入口。
- 查看聊天记录只读取原会话已保存的结果，不调用模型；当前没有供应商状态轮询接口，不能把重读历史称为已确认恢复。
- 幂等终态保持未知证据优先；明确中转拒绝与真正未知分开，结算冲突进入核对状态，不改写钱包。
- 提示词、A/B/C 步骤、智能体名称、模型目录及配置记录不属于本源码锁，不因余额或故障隐藏模型。
- 连接通知和心跳只证明传输状态；仅实际非空思考内容能触发思考面板。阶段提示使用智能体用语，正文开始后不因迟到事件回退。
- 实际可展示的思考内容及时呈现，首次思考展开，正文开始或流结束自动折叠一次；同阶段的增量不覆盖用户手动开关。空白思考不建面板，失败和未知不能冒称思考正常完成。
- 前端显示提速保持完整字形、首字立即、单调追加、单一 RAF、会话隔离与停止清理；不把动画加快称为上游推理提速，不为界面效果降低思考配置。

## 防误改机制

清单逐文件保存 SHA-256。校验默认只读；文件缺失、摘要变化、清单缩水、无效路径、链接或重复路径都会阻止继续。没有自动重新封存、环境变量跳过或关闭参数。校验器和负例测试也在保护范围内。

`pnpm run engineering:check` 首先调用同一只读校验器；发布总检查沿此工程入口执行。标准本地构建入口若已接入，必须在停预览、改版本、开始构建之前校验。构建入口另受提取专项锁保护；是否已经接入及对应授权由该次不可变交接说明，不能凭本合同文字推定已接入。

修改受保护文件前先校验并明确变更范围；用户已授权本轮聊天修复与建锁，不构成未来无关功能随意修改聊天链路的授权。今后有明确聊天变更需求时，在该次授权范围内审阅差量、执行受影响回归，再手工记录新基线和交接。

这是标准工程流程的防误改保护，拥有相同文件权限的人可以同时改源码与校验器；不是操作系统权限锁。大型聊天集成文件也受保护，改动其中其他业务时同样会提醒复核聊天影响。

## 验证边界

错误分类、未知结果防重发、明确拒绝、故障界面和保护篡改测试分别提供证据。零网络测试证明合同，不证明中转通道已恢复。充值后实际恢复只能由同通道的一次新成功请求及其结果回执证明；历史未知记录不因充值被改写。运行版本和构建身份以实时检查及不可变交接回执为准。
