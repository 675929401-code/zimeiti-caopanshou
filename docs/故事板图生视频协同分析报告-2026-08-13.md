# 故事板图生视频协同分析报告

> 研究日期：2026-08-13  
> 核心问题：为什么一张包含四至五格的图片，可以配合一段视频 Prompt 生成连续的正常视频

## 0. 核心答案

对标链路不是把四至五格拆成四至五个视频任务，也不是把每格分别上传。其实际方式是：

1. 故事版智能体针对一个已分段的口播单元，输出一段**故事板生图 Prompt**和一段**整合图生视频 Prompt**。
2. 用户把两段 Prompt 复制到分镜工作台的同一张镜头卡片。
3. 图片模型一次生成一张四至五格故事板。
4. 工作台把这张故事板的公网图片地址作为唯一上游图像，连同整段视频 Prompt 一次提交给视频模型。
5. 视频 Prompt 按 `第 1 格 → 第 N 格`规定动作、运镜和转场，并要求输出全屏连续视频。
6. 视频模型把多格图当作时序视觉参考，不把网格本身当成最终画面。

因此，真正的控制组合是：

`一张多格时序地图 + 一段逐格执行指令 + 一个十秒图生视频任务`

## 1. 已验证的实际提交链路

### 1.1 生图阶段

工作台卡片向图片模型提交：

- 图片模型；
- 故事板生图 Prompt；
- 可选参考图 URL，最多五张；
- 画面比例；
- 图片分辨率。

图片任务异步执行。成功后，卡片得到一张可公开读取的故事板图片 URL，并显示预览、查看和下载入口。

### 1.2 视频阶段

同一卡片解锁视频按钮，提交：

- 视频模型；
- 一整段图生视频 Prompt；
- `imageUrls: [故事板图片 URL]`；
- 视频分辨率；
- 时长；
- 质量档位。

这里没有按 Frame 拆成多个图片 URL。整个故事板只作为一个图像输入。

### 1.3 结果阶段

工作台通过实时进度或异步记录获得视频结果。案例成片显示：

- 镜头按格号顺序出现；
- 输出是正常全屏画面，不保留网格；
- 故事板中的角色、道具、包装和动作方向能被延续；
- 并非每次都完美，模型仍可能跳格、融合镜头或发生身份漂移，因此 Prompt 必须包含读取协议和质检门槛。

## 2. 参考图与视频 Prompt 的职责边界

### 2.1 故事板负责“看起来是什么”

它负责：

- 人物、宠物、服装、毛色和比例；
- 场景、材质、灯光和色彩；
- 每个镜头的构图和动作起点；
- 道具状态和空间方向；
- 问号、桃心、警示、教学窗等语义载体的视觉形态；
- 镜头先后顺序。

它不负责描述完整的运动过程。

### 2.2 视频 Prompt 负责“接下来怎么演”

它负责：

- 从哪一格开始；
- 主体先做什么、再发生什么；
- 表情、身体、道具和环境如何响应；
- 摄像机怎样推、拉、摇、移、跟或切；
- 语义包装如何出现、变化或消失；
- 如何衔接下一格；
- 最后一格如何稳定落幅。

它不应重复整套角色设定、图片规格和创作方法论，更不能写成“必须使用参考图、不得重新设计”一类占据主体篇幅的说明书。

## 3. 为什么一段合并 Prompt 比四段独立提交更符合对标

帮助中心截图把四个格子的动作都写在同一个代码框中；工作台每张卡片也只有一个视频 Prompt 输入框。实际视频提交一次完成。

这种方式有四个优点：

1. 模型能看到完整因果，不会把四个镜头当成四个互不相关的小视频。
2. 角色与场景只在同一个生成任务中演进，连续性优于分四次生成后拼接。
3. 转场和运动方向可以在同一 Prompt 中明确交接。
4. 用户无需反复上传、下载、绑定首尾帧，符合对标“一张卡片两次点击”的效率。

## 4. 案例视频验证结果

### 4.1 宠物医院长案例

成片按故事板中的视觉主题依次出现：宠物医院、毛发龙卷、维生素 B、放大镜与泪流、维生素 A、吃食、体重秤、腿部摇晃、维生素 D、环境风险提示。

可确认的协同规律：

- 毛团、旋风、卡片、秤和警示标识不是后期随机添加，而是先存在于故事板中，再由视频延续。
- 镜头输出为全屏，故事板白色注释条没有作为字幕保留。
- 动作密度高，但个别角色细节会漂移，说明故事板可以显著约束模型，却不能替代明确的身份和顺序指令。

### 4.2 金毛与主人案例

十秒内出现：幼犬奔向主人、主人离开、幼犬抬爪挽留、坐下失落、回忆泡泡、含泪眼睛特写。

这证明多格故事板不仅适合科普道具，也能表达连续情绪故事。镜头之间必须有同一动作或视线线索，否则容易成为图片轮播。

### 4.3 Seedance 垂直案例

成片依次覆盖放大镜与泪流、维生素 A、进食、体重秤等四拍。说明同一方法可以适配竖屏，但四格图的内部构图必须给每个主体留足裁切安全区。

### 4.4 Veo 家庭猫案例

成片从地面追虫转入窗边、卧室和人物反应，整体较自然但夸张度较弱，并存在新增人物的倾向。说明模型能力和风格倾向会影响结果；工作台应允许换模型，但故事板与 Prompt 的合同保持不变。

## 5. 整合视频 Prompt 的正确结构

一段十秒视频 Prompt 应只包含一个总读取协议和四至五个按格执行的动作段。

### 5.1 总读取协议

推荐只保留必要信息：

```text
把参考故事板按 Frame 1 至 Frame N 作为连续时间顺序，生成一条正常全屏的10秒视频。每一格只作为对应镜头的构图和角色依据；不要展示网格、分隔线、Frame注释条或分屏。锁定故事板中的角色、服装、犬种、场景、道具、材质、光影和色彩。
```

### 5.2 每格动作段

每格采用：

`Frame N（约起止秒）：主要运镜 + 主体明确动作 + 表情/身体反应 + 道具或环境反馈 + 语义包装运动 + 向下一格的衔接。`

例如：

```text
Frame 2（约2.2-4.4秒）：快速横移跟随柯基冲向门口，前爪刚触地便急刹，后腿仍向前滑，耳朵猛然竖起、瞳孔收紧；主人手里的旅行包从右侧前景掠过，胸口心跳波纹连续扩散两次，柯基抬头追随旅行包，把视线交给下一镜。
```

这是一条“怎么演”的指令，不是对画面的解释。

### 5.3 时间分配

- 四格：每格约 2 至 2.5 秒，允许高潮镜头略长。
- 五格：每格约 1.6 至 2.2 秒，最后一格保留稳定落幅。
- 时间不是平均分配的数学题，应由动作复杂度决定。
- 一格最多一个主动作和一个次反应，避免十秒内塞入无法执行的事件清单。

## 6. 连续性的五个交接点

相邻格之间至少使用一个可见交接点：

1. **动作交接**：上一格抬爪，下一格从爪落地开始。
2. **视线交接**：上一格看向右侧，下一格右侧目标进入。
3. **道具交接**：包、食物、卡片、玩具等保持位置和状态变化。
4. **方向交接**：角色离开或进入画面的方向一致。
5. **效果交接**：心跳波、气味轨迹、闪光或警示由上一格扩展到下一格，而不是突然换一种包装。

只有主题相同而没有任何交接点，不算连续镜头。

## 7. 语义包装如何从静态图延续到视频

包装必须先在故事板中给出形态，视频 Prompt 再给它运动规律：

| 故事板中的静态形态 | 视频中的执行动作 |
| --- | --- |
| 胸口一圈心跳波纹 | 波纹随呼吸扩散两次，第二次更急促 |
| 头顶问号 | 问号先弹出、轻晃，角色左右看后缩小消失 |
| 两个角色之间桃心 | 桃心从两者视线交点浮起，随靠近轻轻放大 |
| 肠道局部教学窗 | 教学窗从侧边展开，食物光点沿简化路径移动 |
| 警示牌 | 角色触发风险时牌面快速弹出并轻震一次 |
| 气味轨迹 | 粒子从气味源弯曲流向鼻尖，角色沿轨迹追踪 |

如果故事板没有画出对应元素，只在视频 Prompt 里临时要求复杂包装，模型更容易忽略或重新设计。因此“先装饰参考图，再让视频延续”是正确方向。

## 8. 声音与口型边界

当前产品不负责自动配音和自动合成，因此视频生成应默认：

- 角色不说话，不做连续对白口型；
- 可以有喘气、爪声、急刹、碰撞、毛发飞散等自然动作声；
- 不生成旁白、歌词、可读字幕和背景解说；
- 口播、字幕和最终配乐由后期独立完成。

这能避免模型擅自让人物开口或制造错误语音。

## 9. 失败模式与根因

| 失败现象 | 根因 | 修正 |
| --- | --- | --- |
| 输出仍是四格分屏 | 未明确“故事板仅作时序参考，输出全屏” | 在总读取协议第一句写明 |
| 只演第一格 | 每格没有动作和时间段，或 Prompt 过长失焦 | 每格一条短指令，格号和秒段清楚 |
| 镜头像图片淡入淡出 | 各格只有场景描述，没有动作前势和物理反馈 | 强制主动作、次反应、环境反馈 |
| 跳过某格 | 中间格与主因果无关，或没有交接点 | 删除凑格镜头，补动作/视线/道具交接 |
| 角色漂移 | 故事板各格本身不一致，或视频 Prompt 允许重设计 | 先拒绝不合格故事板，再提交视频 |
| 包装消失 | 只在文字里提包装，故事板未呈现 | 先在参考图中形成可见元素 |
| 人物突然说话 | Prompt 写了“解释、告诉、讲述”等行为 | 改成可见动作，明确无对白口型 |
| 出现血腥器官 | 把“内部机制”写成解剖 | 改为独立局部教学窗或友好示意图 |
| 注释条进入成片 | 未区分制作标注与最终画面 | 明确不要网格、分隔线和注释条 |

## 10. 提交前质量门槛

只有同时满足以下条件，视频按钮才算具备“可生成”质量，而不只是技术上解锁：

1. 故事板格数与视频 Prompt 的 Frame 数完全一致。
2. 每格都有一个可执行主动作，且不是重复姿势。
3. 相邻格至少有一个连续性交接点。
4. 视频 Prompt 明确输出正常全屏视频，不显示故事板版式。
5. 主体、道具、方向和语义包装与故事板逐格对应。
6. 故事板本身不存在犬种、服装、场景或风格漂移。
7. 抽象知识点已有可见载体，且不血腥、不令人不适。
8. 没有对白、旁白、字幕和不受控口型要求。
9. 整段在目标时长内能够完成，不把多个复杂动作塞进同一秒。
10. 最后一格有明确落幅，不在动作中途突然结束。

## 11. 对新版智能体输出的要求

每个原文段落必须输出两个可整体复制的代码块：

1. `故事板分镜图 Prompt（共4格/共5格）`
2. `图生视频 Prompt（对应第1格至第4格/第5格）`

第二个代码块内部按 Frame 分段，但仍是一整段提交文本。工作台不解析 Frame 字段，也不把它拆成多个视频卡片；用户复制一次、粘贴一次、提交一次。

这就是后续故事版智能体与分镜工作台之间的稳定接口。
