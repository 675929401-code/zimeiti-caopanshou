# 分镜与 AI 视频历史闭环合同

来源：用户 2026-10-18 本聊天重新梳理的要求。范围仅 `/storyboard-workbench` 与 `/video`，先完成分镜并验收，再接入视频页。本合同取代这两页历史的旧缓存/排序建议，不改变其他业务存储策略。

## 用户流程与唯一归属

账号权限 → video_tasks 历史投影 → 共用历史面板及局部三主题样式 → history / access-ticket / 流式代理 → 上游视频与用户浏览器缓存。

1. 生成任务仍由现有流程留档；历史以 taskId 唯一识别。分镜与普通视频通过 surface 隔离。同一卡片再次生成保留独立结果与费用记录。
2. 列表按北京时间的日期、制作批次、卡片序号组织。批次按最近提交时间倒序，批内按零基 cardIndex 升序；同卡多次提交按提交时间倒序。分页继续合并原批次。
3. 成功任务以视频卡牌展示；一个大播放器负责点播。读取与下载只使用原结果，不提交新生成。卡片只展示封面、段号、简短状态和必要操作，详细参数按需展开。
4. 视频源由上游提供；平台只存任务、归属、引用和必要状态，不因本功能新增服务器媒体副本。保留鉴权/Range 流式代理。新历史不调用会在服务器下载整段视频的 thumbnail 路由；参考图或本机封面用于卡面，无图时用清楚的占位。
5. 本机完整视频缓存为可选操作，按账号与 surface 隔离。写入全部字节和索引并通过校验后才显示可用。浏览器不支持缓存、空间不足、缓存损坏时仍可尝试原上游播放和下载。已下载到用户自选目录的文件不受历史清理影响。

## 五天与清空

- 已确定终态的记录保留至 completedAt + 120 小时；旧终态缺 completedAt 时回退 createdAt。时间不合法不猜测删除。任务排序仍用提交时间。
- 进行中、上游结果未知及费用未确定的任务受保护。账务使用明确终结白名单；不得按一个不完整的排除列表清理。
- API 读取执行五天可见窗口；浏览器打开、恢复焦点及定时复查时更新列表和清理到期本机字节。关闭的浏览器不承诺后台定点物理删除。
- 一键清空按当前账号、当前页面、点击时 cutoff 清除可清理历史；更新 history_hidden_at，不删除任务或账务。不取消进行中的生成，不删除上游文件。界面明确报告已清数量与保留数量。
- 返回具体已隐藏 IDs；本机缓存写墓碑后删除大字节。跨标签页通知和服务端 ID 对账防止旧副本重新出现；在途缓存保存不得越过清空。失败时保留可重试的相同 cutoff，不显示假成功。
- 用户补充授权：本轮旧数据清理在两页验收后执行，覆盖当前本地环境管理员及所有用户的这两页旧历史。按固定服务端截止时间清理已结束且费用确定的记录，保留未决任务和账务；先记录范围与数量，再执行并回读。普通用户界面的清空始终仅针对自己的本页历史。

## 验收顺序与标准

1. 策略/接口/缓存离线边界：120小时、晚完成、未知账务、隔离、分页、同卡多版本、清空竞态、重复清空与失败恢复。
2. 单一窗口构建并确认 127.0.0.1:5000 runningLatest=true。
3. 分镜：lattice / soft-white / crystal-aurora，1440×900 与宽屏；空态/失败/加载/大批次滚动、播放/暂停/拖动/下载、关闭/Esc/焦点、缓存禁用和容量失败、过期/清空/跨标签页。
4. 通过后 `/video` 复用同一组件，保留原重新载入参数、选择及批量下载能力，验证两页隔离；回归至少两个相邻页面。
5. Chromium、Edge、Firefox、WebKit 按本机实际可用运行时检查；未安装或不可运行必须单列，不把一种引擎通过称作所有浏览器通过。可解码测试媒体证明播放器，不冒称付费供应商生成。
6. 复核实际当前账号已有任务的读取、播放与清理，保留运行身份和结果；没有媒体就不制造付费生成。

播放可能被浏览器策略阻止时，保留可点击播放按钮并根据 play() 的结果更新状态；缓存是渐进增强。参考：[MDN play](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)、[CacheStorage](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage)、[dialog showModal](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/showModal)。
