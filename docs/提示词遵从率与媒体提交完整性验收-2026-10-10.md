# 提示词遵从率与媒体提交完整性验收

更新时间：2026-10-10
范围：AI 生图、普通视频、AutoDL MiniMax H3 视频
当前等级：`schema_verified / zero-cost`；本轮未发供应商请求、未扣费、未写数据库、未构建、未启停、未部署。

## 1. 结论

当前代码已经具备比旧历史更完整的请求证据：生图 `image_generation_request_snapshot.v2` 能保存原始/有效提示词、画幅、分辨率、参考资产指纹、协议、像素目标和请求指纹；视频 `video_generation_request_snapshot.v1` 能保存原始/有效提示词、负向提示词、独立参考角色、目标/实际提交时长、画幅、分辨率、FPS、seed、音频开关、模型/适配器身份和 provider payload 哈希。生图成功历史与视频历史都能回读对应快照。

这些证据只证明“平台接受并记录了什么”。它们不证明图片里真的有指定主体，也不证明视频动作顺序、角色一致性、禁止项、声音或时长语义已经遵从。旧的成功任务、HTTP 200、任务 ID、文本关键词命中和 provider payload 哈希均不能替代输出媒体审查。

H3 的正确合同是“不支持的控制项在派发前明确拒绝”：`autodl_comfyui_workflow` 的真实工作流 body 会发送 prompt、duration/audio_duration、resolution、首尾帧或 `ref_image_*`、`ref_audio_*`；`negative_prompt` 和显式 `generate_audio` 若未由当前协议配置声明支持，会被统一参数门禁在桥接、预留、计费和供应商 POST 之前以 422 拒绝，`task_submitted=false`、`price=0`。参考音频输入不等于“生成音频开关”。零网络回归必须持续覆盖 hosted H3 与 selfhost H3，防止未来配置变化把“不支持”退化成静默丢参。

## 2. 影响链

```text
业务约束
  → 页面字段与素材角色
  → /api/image/generate 或 /api/video/generate
  → 模型能力/协议门禁
  → 不可变请求快照
  → 具体 provider adapter 请求体
  → 上游任务/输出资产
  → 历史读回与账务
  → 媒体元数据 + 帧/时间段/音轨人工或多模态审查
```

提示词文案与内部字段分开：用户提示词、有效提示词、技术参数、素材角色、provider 字段、输出观察分别计分。任一层不能替代下一层。

## 3. 当前提交与历史证据审计

| 链路 | 已确认 | 仍不能确认/当前缺口 |
|---|---|---|
| 生图 | 公共请求白名单；prompt/style/画幅/分辨率/参考图；负向、seed、mask、quality 和 provider 专属字段明确拒绝；固定单图；v2 快照及成功历史回读 | 参考图快照主要保存去签名指纹和总体用途，不能单独证明各图的视觉责任；provider request body 与生成图语义需金丝雀现场证据 |

## 4. 量化口径

每个用例输出四个互不混加的指标：

1. `submissionCompleteness`：页面/快照/历史/provider 观察是否逐字段一致；硬字段必须 100%。
2. `promptLexicalCoverage`：有效提示词是否包含固定约束锚点；只诊断编译丢词，永远不计入画面得分。
3. `outputSemanticAdherenceObserved`：仅对已经有帧、时间段、音轨或媒体探针证据的输出约束加权评分。
4. `outputSemanticEvidenceCoverage`：输出约束中有可审查证据的比例；低于 100% 时结论只能是 `incomplete`。

证据类型也必须匹配约束层：尺寸、时长和音轨有无只接受输出文件的媒体探针；动作顺序必须有时间段/人工/多模态复核；H3 的“确为雨声且无意外人声”必须有音频片段或听审，单纯检测到音轨存在仍不够。请求快照与历史读回只计提交完整性，不能拿来证明输出元数据或内容。

硬失败包括：关键字段未提交或历史读回不一致；供应商派发次数不是 1；出现自动重试；模型/适配器身份缺失；图片比例/分辨率不符；视频时长/分辨率/音轨不符；主体或动作硬约束失败；禁止项出现；把提示词文本当作视觉、时间或声音证据。

图片、普通视频、H3 视频固定题集见 `scripts/fixtures/prompt-adherence/paid-canary-suite.v1.json`。H3 的 1920×1056 输出必须报告为规格差异，不能四舍五入称作 1080P。

## 6. 后续各一次真实付费金丝雀

执行人必须先从当前模型目录读回并锁定：`sourceVersion`、Build ID、`runningLatest=true`、公开模型 ID、内部模型 ID、provider、`protocol_type`、模型版本、适配器版本、价格与输入能力。旧模型名和旧任务不能代替当次身份。

每条链最多一次 provider POST、唯一请求键、自动重试 0。顺序为：

1. 生图：使用固定图例；记录浏览器提交、v2 快照、脱敏 provider 字段、任务/资产、成功历史读回、媒体尺寸、净扣费；随后逐项做视觉审查。
2. 普通视频：选择确实支持固定时长/分辨率/音频关闭的代表模型；记录 v1 快照、payload hash、脱敏 provider 字段、任务、历史、ffprobe、净扣费；逐帧/时间段审查。
3. H3：选择精确 workflow mode；先用零网络用例证明未声明的 `negative_prompt`/显式 `generate_audio` 在派发前 422 且 provider calls=0，再按固定主提示词与参考音频提交一次。记录 `ref_image_*`/`ref_audio_*` 数量、时长、分辨率、任务、历史、ffprobe 与净扣费；审查身份、动作、负向语义和音轨。

执行后把计划副本补成 `media_prompt_adherence_run.v1`，再运行：

```powershell
node scripts/verifiers/prompt-adherence/media-prompt-adherence-verifier.mjs --suite scripts/fixtures/prompt-adherence/paid-canary-suite.v1.json --mode evaluate --run .codex-evidence/media-adherence-p0/paid-canary-run.json --out .codex-evidence/media-adherence-p0/report.json
```

只有三例 `submissionCompleteness=100`、`outputSemanticEvidenceCoverage=100`、硬失败为 0，才可以写“本次固定题集通过”。这仍是三个代表模型的当次证据，不代表所有模型、所有提示词或生产环境整体通过。
