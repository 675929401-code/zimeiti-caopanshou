## 局部恢复方法

### 1. 主题机制

目标文件：`themes.ts`、`theme-init.tsx`、`layout.tsx`、`user-theme-switcher.tsx`。

- 删除 `layout.tsx` 对 `theme-polish.css` 的导入。
- 将首屏主题脚本恢复为改前行为时，只恢复 `layout.tsx` 中“在 React hydrate 之前应用用户主题偏好”注释后的单个内联脚本，不动其余登录保护脚本。
- 将 `ThemeInit` 恢复时，只恢复组件内首次 `useEffect`；不要覆盖整文件。
- `UserThemeSwitcher` 改前为空组件，若切换器引起问题，可将其恢复为 `return null` 并删除侧栏中的单个组件引用。

### 2. 导航

目标文件：`app-sidebar.tsx` 与 `theme-polish.css` 的 `.sidebar-*`、`.theme-switcher-*` 规则。

- 删除 `UserThemeSwitcher` 导入及用户行中的单个 `<UserThemeSwitcher />`。
- 删除 `theme-polish.css` 中导航相关选择器即可回到原视觉；会话、余额、公告和用户菜单逻辑不受影响。

### 3. 应用广场

目标文件：`agent-marketplace.tsx`（只作为选择器证据，不计划改变布局算法）与 `theme-polish.css` 的 `.marketplace-*`、`.agent-card-hover` 规则。

- 若卡片密度不合适，仅删除主题文件中的应用广场段落。
- 不回滚 `gridStyle`、排序、拖拽、卡片点击或后台布局配置，因为本轮不修改这些逻辑。

### 4. 共享二级页

目标文件：`sub-page-header.tsx` 与 `theme-polish.css` 的 `.sub-page-*` 规则。

- JSX 只新增语义类名和焦点样式锚点；删除新增类名不会改变返回、新窗口和右侧操作逻辑。
- 若只需恢复某个二级页，不要改共享头，改为在该页面根节点取消 `secondary-workbench` 类。

### 5. 登录页

目标文件：`login-form.tsx` 与 `theme-polish.css` 的 `.login-form-shell`、`.login-panel` 规则。

- 删除根容器/玻璃面板新增类名即可恢复原样。
- 登录模式、表单字段、验证码、安全问题和提交处理均不属于本轮改造，禁止在视觉回滚时覆盖。
