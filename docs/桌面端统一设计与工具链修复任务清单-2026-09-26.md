# 桌面端统一设计与工具链修复任务清单

日期：2026-09-26  
执行范围：自媒体操盘手电脑端 Web，固定验收宽度 1280、1440、1920。  
主题范围：默认深色“深空晶层”与浅色“玉瓷暖白”。  
保护范围：漫剧创作、带货创作仅统一外部导航壳，内部视觉保持各自独立。

## 目标重述

以商业交付标准统一平台的功能结构和视觉系统：先修正功能链、页面骨架和状态语义，再建立统一字体、间距、组件、配色和动效，最后让深浅两套主题共享同一套业务界面与验收合同。默认深色主题是主设计基准，浅色主题同步映射，不作为独立页面或后补皮肤。

## 执行顺序

### 第一步：功能与界面骨架

1. 将视频、文案、批量与搜索统一到 active `coze_multifunction_extract`，修复安全下载、checkpoint、状态恢复和报价来源。
2. 锁定三合一文案既有成功链路，并将旧 `extract_video` / PPT6 限定为历史 checkpoint 恢复兼容。
3. 修复工具箱四功能导航、状态语义和切换保活。
4. 修复分镜 312px 左栏、默认三卡与参数可见性。
5. 抽取并接入共享 ModelBadge。

### 第二步：统一设计与主题

1. 建立字体、间距、圆角、边框、表面、状态与品牌色的语义 token。
2. 以“深空晶层”为默认商业主基准，并同步“玉瓷暖白”。
3. 统一九项四字导航、顺序和约 200ms 动效。
4. 让两主题共享业务首页并恢复滚动。
5. 回归视频、图像、声音、封面及漫剧/带货保护边界。
6. 统一深浅导航的层级、语义图标色、快捷入口当前态和头像回退视觉。

### 第三步前置：账号会话治理

1. 以服务端会话为唯一有效性依据，最多保留最新两条有效会话。
2. 登录失败、会话过期、账号停用或被第三次登录撤销时，清理本地身份并返回主页。
3. IP 和浏览器摘要仅用于审计，不用共享 IP 代替账号会话，也不把同一网络中的不同用户误判为同一人。
4. 通过数据库合同和真实浏览器分别验证并发上限、定向退出和失效跳转。

### 第三步：合并与真实验收

1. 完成零网络、零业务写入的源码与浏览器门禁。
2. 构建 F 盘当前版本，核对源码版本、BUILD_ID 与 `runningLatest=true`。
3. 在 1280×800、1440×900、1920×1080 下验证两主题与目标页面。
4. 只读重放一条既有成功文案历史，并核对视频、文案、批量、搜索四项公开运行目录均来自同一个三合一插件。
5. 零网络验证旧 PPT6 检查点仍可恢复且不会重放供应商；旧 `extract_video` 配置不得出现在新任务运行目录或后台可启用项中。
6. 在其余门禁通过后，只提交一次有明确限额且禁止自动重试的 Coze 视频请求，保存完整下载、播放解码、历史刷新和账务证据。

## 统一设计标准

- 页面使用单一主滚动容器，禁止横向溢出和隐藏关键操作。
- 普通正文不低于 14px；辅助信息不低于 12px；输入正文不低于 13px。
- 普通文本对比度目标不低于 4.5:1；控件边界与大字目标不低于 3:1。
- 颜色按约 70% 表面、25% 中性色、5% 品牌与状态色分配。
- 品牌色只用于选中态、主按钮和焦点环；成功、警告、错误只表达真实状态。
- 工作台优先实色表面、单层边框和轻阴影，取消网格、霓虹、发光与多层玻璃堆叠。
- 交互动效控制在 180–240ms；减少动效偏好下缩短到近即时反馈。
- 显示名称与稳定 key、路由、存储值和数据库 ID 分离。

## 验收判定

只有同时满足以下条件，才能写“问题已解决”：

1. 当前 F 盘源码完成构建并由 5000 端口最新运行包提供服务。
2. 分镜三个桌面宽度均为 312px 左栏和每行三卡。
3. 工具箱四功能切换、输入保活、URL、状态与结果区工作正常。
4. 两主题的主题名、语义色、首页、导航、字体与动效均在真实 DOM 和计算样式中生效。
5. 漫剧和带货内部视觉未被共享主题污染。
6. 文案提取只读重放通过；视频、文案、批量与搜索共用 `coze_multifunction_extract` 的凭据、价格和可用状态，旧 `extract_video` / PPT6 不参与新请求。
7. 新视频任务的 Coze 供应商提交至多一次；检查点恢复带有 `provider handler skipped` 服务端证明，下载完整、可播放、历史可恢复，钱包扣款与收入记录和三合一插件报价一致；旧 PPT6 检查点仅能恢复，不能触发新提交。
8. 页面错误、控制台错误、失败响应、横向溢出和破图均为零。
9. 同一账号最多两条有效会话；第三次登录只撤销最旧会话，旧页面自动回到主页。
