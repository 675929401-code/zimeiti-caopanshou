# 分镜工作台源视频编辑模型误入修复记录（2026-08-17）

## 可复现问题

1. 分镜工作台“图生视频模型”列表错误展示 `Omni Video Edit · secure-skill`。
2. 该模型的公开能力为 `requiresSourceVideo=true`，数据库协议配置也要求一条公网可访问的 HTTPS 源视频。
3. 分镜工作台只有故事板图片输入，提交体只携带 `image_url`；因此两次镜头1任务均失败，原始错误为“必须提供一条可公开访问的 HTTPS 源视频 URL”，两次 `price_charged` 均为 0。
4. 旧错误分类未识别“必须提供源视频”，前端只显示笼统的“生成失败，请稍后重试”。

## 修复范围

- `src/components/storyboard-workbench.tsx`
  - 读取并保留模型能力 `requiresSourceVideo`。
  - 分镜工作台只显示支持图片输入且不要求源视频的模型。
  - 在生成入口增加防御性门禁，避免历史状态或异常数据绕过列表过滤。
- `src/lib/video-error-policy.ts`
  - 将源视频缺失归类为 `VIDEO_INPUT_INVALID`、不可自动重试，并返回“必须先上传源视频”的可执行提示。
- `scripts/verify-video-channel-repair.ts`
  - 增加源视频缺失错误分类回归。
- `scripts/verify-storyboard-video-model-filter-ui.mjs`
  - 验证分镜工作台隐藏该模型、`/video` 专用页仍保留、没有生成请求和页面错误。

未改数据库模型开关、价格、渠道凭据、全局视觉主题、三张导演卡 Prompt、自由画布或视频模型适配器。
