# 自媒体操盘手 · 本地版本与验收协议

> 本协议只负责本地源码身份、构建、本地验收、证据和交接。GitHub 远端写入、制品、服务器候选、生产切换、回退与线上验收只服从 `F:\总项目文件\Skill存储系统\99_系统协议\02_操作协议\自媒体操盘手部署执行规约-当前版.md`。

## 1. 权威边界

- 唯一本地源码：`F:\总项目文件\Skill存储系统\01_网页开发项目\自媒体操盘手\当前版本`。
- 本协议不创建第二开发工作区，也不定义发布仓、远端、服务器路径或生产动作。
- 任何旧发布副本、旧自动发布动作、服务器收包队列、直推脚本和标签式稳定版口径都不是现行入口；具体历史名称只保留在审计记录和版本历史中。
- 旧回执中出现上述名称，只能说明历史发生过什么，不能授权或指导当前操作。
- 当前任务和执行人来自 `协作交接.ps1 Status` 与最新不可变回执；本协议不保存动态状态。

## 2. 身份分层

| 身份 | 证明什么 | 不能证明什么 |
|---|---|---|
| sourceVersion / 源码摘要 | 本地源码内容身份 | 构建、GitHub 或生产已经更新 |
| Build ID / 构建指纹 | 某次本地构建与源码/环境的绑定 | 浏览器功能或生产通过 |
| Git SHA | 某个远端代码提交 | 制品、服务器或域名已使用该提交 |
| artifact SHA-256 / releaseId | 不可变候选制品身份 | 生产指针已切换 |
| 生产指针、进程身份与线上证据 | 实际运行版本与线上行为 | 未验证的上游能力或数据安全 |

这些身份必须在回执中关联，不能互相冒充。相同源码重复构建不应伪造新源码版本；源码、依赖、环境或关键配置变化后，受影响的旧构建/验收证据失效。

## 3. 固定信息与动态信息

| 类型 | 保存位置与规则 |
|---|---|
| 固定本地约束 | 本协议和源码 `AGENTS.md`；只保存长期不变量 |
| 当前任务与执行人 | `协作交接.ps1 Status` + 最新不可变回执 |
| 每轮源码/构建身份 | `public/version.json`、构建凭据与操作日志自动生成 |
| 本地验收结果 | 绑定本轮源码与 Build ID 的结构化证据 |
| 模型、价格、配额、用户和素材 | 当前数据库/后台/对象存储，不写进版本规则 |
| 凭据 | 受控环境；文档只引用 `99_系统协议/凭据速查.txt` |
| 远端与生产状态 | 部署权威规约要求的实时检查与回执 |

操作日志位于项目相邻 `当前版本.执行日志/`。日志追加保存阶段事实，但不产生授权，也不能用旧日志替代当前源码、进程和回执。

## 4. 本地修改与验收顺序

1. 读取根引导、项目工作台、Status/latest、当前任务清单和源码 `AGENTS.md`。
2. 有写入时确认已 Begin；记录本轮目标文件、现有差异、限定快照/可逆补丁和 SHA-256。
3. 修改源码；新问题进入同一问题台账，状态按“待处理 → 修复中 → 待验证 → 已验证”推进。
4. 完成后按现行脚本更新 sourceVersion。正常构建若已自动执行该步骤，不重复升号。
5. 先跑与改动直接相关的类型、lint、单元/合同检查；再执行必要构建。构建期间源码变化则该构建无效。
6. 启动或复用 5000，使用根启动器证明进程来自 F 盘当前构建且 `runningLatest=true`。
7. 在真实浏览器验收精确目标路由，并按源码 `AGENTS.md` 回归至少两个相邻页面；API 200、静态检查和构建成功不能替代。
8. 将真实结果写入结构化证据、任务清单和操作日志；失败、未测和 UNKNOWN 必须保留。
9. Complete 交接，分别报告源码、构建、本地验收和未完成项。

做到第 9 步只代表本地阶段完成。任何 GitHub、制品或服务器动作都必须转到部署权威规约重新判断授权与门禁。

## 5. sourceVersion 规则

- `public/version.json` 是公共源码身份记录；目录名不随产品版本重命名。
- sourceVersion 由现行版本脚本生成，必须单调、可追溯并绑定内容摘要；不得手工改数字制造“新版”。
- 同一份源码进入后续阶段应保持同一 sourceVersion；只有源码实际变化才形成新版本。
- V2.5、V2.6、Rxxx 等旧别名只用于查历史，不能作为启动、回滚或稳定性依据。
- `GET /api/version` 必须与磁盘构建凭据、实际进程和源码指纹一起判断；单独返回版本字符串不够。

## 6. 本地验收证据

本地发布资格证据必须是结构化、可复核并绑定当前身份的文件，至少包含：

```json
{
  "schemaVersion": 1,
  "stage": "local-release",
  "sourceVersion": "实际值",
  "buildId": "实际值",
  "fingerprint": "实际完整摘要",
  "openIssues": [],
  "checks": []
}
```

每个检查项必须包含稳定 ID、`passed` 状态、证据路径与 SHA-256。复制示例、空数组、任意文本文件或一句“通过”都不是证据。源码、环境、Build ID、依赖或底层证据变化后必须重新核对。

覆盖范围按本轮影响选择，但下列类别不能用一个笼统结果合并：

- source/runtime 身份；
- 目标功能及失败恢复；
- 账号权限、隔离、会员、账务与幂等；
- 数据/素材持久化和历史恢复；
- UI、主题、导航、响应与可访问性；
- 并发、队列、worker 和取消/重试；
- 安全、日志脱敏、备份与恢复。

真实付费、真实上游生成和生产专属项目没有实际执行时必须写“未验证”，不能用管理员免扣费、task ID、queued 或零费用合同测试代替。

## 7. 本地备份与恢复

| 对象 | 本地做法 | 边界 |
|---|---|---|
| 本轮源码 | 限定文件快照/补丁 + SHA-256 + 变更清单 | 只恢复本轮记录的文件 |
| 完整代码灾备 | 经授权的干净远端固定提交 | 只 clone 到新隔离目录核验，不覆盖事实源 |
| 依赖 | 锁文件、固定 Node/pnpm 与受控缓存 | 不为排错自动升级依赖 |
| 构建 | 可验证的 Build ID 与来源凭据 | 旧包不能冒充新源码预览 |
| 数据/素材 | 独立快照、对象清单和异地副本 | 代码回滚不自动回滚用户数据 |
| 密钥 | 受控运行环境与加密备份 | 不进 Git、制品、日志或文档 |

Windows 构建目录可能含 junction。需要归档 `.next` 时只使用项目现行归档脚本和同盘原子重命名，先停止相关进程并核对边界；禁止递归移动/删除可能跟随链接的目录。

用户要求“撤销”时只恢复本轮明确记录的本地文件。数据库、对象存储、GitHub 和生产回退是不同动作，必须按各自权威规则另行处理。

## 8. 效率与失败恢复

- 先做便宜、定向的检查，风险上升再做完整构建和全链验收；同一事实源同一时刻只跑一个构建。
- 不重装未变化且可用的依赖；不把 node_modules、缓存、备份、用户媒体或数据库塞进代码制品。
- 已验证且绑定条件未变化的证据可复用；只重跑受变更影响的阶段。
- 外部请求超时先查原任务身份和终态，不盲目重发付费请求。
- 分别记录编辑、检查、构建、浏览器验收及后续部署阶段耗时，按证据定位瓶颈；不靠跳过门禁换速度。

## 9. 当前状态报告格式

每次只报告已实时核对的层级：

1. 本地源码身份；
2. 本地构建身份及是否 `runningLatest=true`；
3. 本轮实际通过/失败/未测项目；
4. Git、制品、候选和生产若未按部署规约实时核对，明确写“本轮未核对”；
5. 剩余问题、运行中任务和下一项需要的授权。

旧生产快照、旧执行人、旧远端结构和旧自动发布说明已从本协议移除；需要追溯时查看版本历史和不可变回执，但不得据此执行。

## 后台配置对账

本地后台的“智能体 → 配置核对”可读取正式站的公开目录，比较各分类、稳定 ID 和配置差异。两端的私有配置由各自已完成安全验证的所有者会话读取。摘要只表示本次观察到的内容；发布版本和实际模型调用分别验收。

本地验收或局部发布前后，运行 `node scripts/compare-public-configuration-readonly.mjs --left http://127.0.0.1:5000 --right https://zyuani8.com --mode informational --out <新报告路径>`，各保留一份；如需直连已核实的源站 IP，可传 `--right-connect-address <源站IP>`，仍校验正式域名证书。`--mode strict` 要求两端所有者诊断也完整，证据不足或字段不一致即失败。`--public-only` 可显式限定到公开范围。命令帮助列出通过环境变量提供各端会话的选项。首期使用旁路报告。离线回归见 `scripts/verify-public-configuration-parity-zero-network.mjs` 和 `scripts/verify-configuration-identity-zero-network.mjs`。
