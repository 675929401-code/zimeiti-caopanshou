# 智能体工程师 5.1 审计与回归报告

## 结论

“边改边忘”不是单一模型问题，而是提示词体积、上下文裁剪、缺少持久需求状态和预设字段 ID 重生成共同造成的。5.1 将 27 个重复模块收敛为 6 个模块，并用可续接的需求账本与稳定协议代替自然语言标题猜测。

## 已确认根因

1. 数据库中的“智能体工程开师 5.0”名称有错字，系统提示词约 18,700 输出 token，先占用了大量上下文。
2. 数据库把 `max_context_rounds/max_context_tokens` 配为 0，并不代表长对话永远完整保留。LLM 路由在历史过长时仍启用 24 轮、32768 token 的快速裁剪。
3. 旧提示词没有完整需求账本；旧消息被裁掉后，早期要求没有任何后继状态可恢复。
4. 旧版 27 个模块重复描述输入路由、意图、格式、稳定性和安全，且“保留冗余、长句、像素级锁定”等规则推动提示词继续膨胀。
5. “默认只给 L2”“未确认不输出最终版”“未授权不全局重构”互相叠加，阻碍自然聊天和局部增量修改。
6. `:::text` 不是平台现有 Markdown 渲染的稳定协议；“不留空行”又和标题、表格、代码块排版冲突。
7. 平台已有轻量防泄露前缀，业务提示词再复制完整安全防火墙只会增加冲突和上下文成本。
8. 后台提问模板在每次转换时使用 `Date.now()` 重建字段 ID；仅修改显示标签或顺序也会让字段身份变化。
9. 新建智能体时，前端版本历史组件使用临时 ID，首次 `pushVersion` 会被跳过，初始提示词版本未可靠入库。

## 实施内容

- `docs/智能体工程师5.1-系统提示词.md`：六模块 5.1 提示词；讨论阶段只输出增量，用户说定稿后才输出完整版。
- `src/lib/agent-engineer-protocol.ts`：定义 `agent_engineer_state.v1`、`agent_prompt_package.v1`、需求账本合并和容错解析。
- `src/lib/agent-preset-schema.ts`：兼容旧数组与版本化 envelope，保留已有 ID，为无 ID 旧字段生成确定性 ID。
- `src/components/preset-template-editor.tsx`：JSON 模式改为带 `schema_version` 的 envelope；编辑、移动、改名不再丢 ID。
- `src/app/admin/page.tsx`：新增和编辑智能体时沿用稳定字段 ID，不再每次用时间戳重建。
- `src/app/api/admin/agents/route.ts`：服务端统一规范预设字段；新增或修改提示词时自动保存版本历史；相关修改会刷新前台智能体缓存。
- `src/app/api/bots/route.ts`：读取旧配置时执行兼容规范化，旧数据不迁移也能获得稳定字段 ID。
- `scripts/migrations/20260814_agent_engineer_5_1.sql`：保存旧配置快照后更新指定智能体，提示词仍在后台 `system_prompt` 可编辑。
- `scripts/migrations/20260814_agent_engineer_5_1_rollback.sql`：从快照恢复名称、提示词、预设字段和上下文配置。
- `scripts/verify-agent-engineer-5-1.ts`：覆盖旧格式、字段改名/排序、版本化 JSON、状态标记、完整机器包和 12 轮不遗忘回归。

## 协议规则

- 提示词文本和显示标题可以自由修改。
- 平台只按 `schema_version`、`artifact_type` 和稳定字段 `id` 识别。
- 旧版数组、`title/label` 别名、`input/text` 类型差异均由兼容层归一化。
- 讨论回复末尾保存完整 `agent_engineer_state.v1`，因此即使早期自然对话被裁掉，最近状态仍携带全部有效需求。
- 完整交付只使用标准 `json` 代码块；生图、视频或画布消费者不得按代码框顺序猜字段。

## 回归风险

1. HTML 注释状态块依赖模型持续输出。若某个模型擅自删除注释，下一轮仍可从最近一次有效状态恢复，但本轮新增要求需从用户消息重新推断。
2. 对没有 ID 且标签完全相同的多个旧字段，兼容层会增加重复序号；保存一次后 ID 即固定。管理员应避免两个字段使用完全相同的显示标签。
3. 自动保存版本历史依赖现有 `prompt_versions` 表。写版本失败不会阻断智能体保存，但会记录服务端错误；部署验收需检查该表权限。
4. SQL 迁移尚未自动执行；执行前应先确认目标 ID 仍为 `agent-1781690935600-gkt1xg`，执行后检查后台名称、提示词、预设输入和版本历史。
5. 迁移备份表仅保存提示词相关字段，并启用 RLS、撤销匿名与普通登录用户权限；禁止把渠道令牌、代理地址或其他整行敏感配置写入迁移快照。

## 验收标准

- 8 至 12 轮连续修改后，第一轮固定要求和禁止回归项仍在账本中。
- 修改提示词模块顺序、中文标题、代码框位置后，机器包解析结果不变。
- 预设字段仅改显示名或移动顺序时，ID 不变。
- 讨论阶段不输出整份提示词；“定稿/输出完整版”后机器包字段齐全。
- 正常闲聊和业务解释可以回答；只有索取隐藏原文、密钥和内部规则时精准拒绝。
