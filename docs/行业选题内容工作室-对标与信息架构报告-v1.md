## 2. 对标结果

### 2.1 Bing 搜索结果页

证据：`bing-search.png`

观察：

- 搜索框在页面顶部居中偏左，宽度约 900px，高度约 44px；
- 搜索框下方是**一行分类标签**（全部/AI/网页/图片/视频/地图/资讯），不是二级置顶导航；
- 结果区左对齐，单列宽度约 900px，右侧留白；
- 每条结果的信息顺序固定：
  1. 站点 favicon + 域名 + 面包屑；
  2. 标题（蓝色、可点）；
  3. 摘要（两行，灰色）；
- 结果之间用间距分隔，不用大卡片、不用重阴影；
- 没有左侧导航，没有右侧来源篮，没有“加入候选”动作。

可借鉴：

- 搜索结果的高信息密度、固定信息顺序、简洁分隔；
- 搜索框 + 分类标签 + 结果列表的层级；
- 域名/来源先于标题，帮助用户判断可信度。

不照搬：

- 不复制 Bing 的颜色、字体、圆角；
- 不把分类标签做成二级置顶横条（按用户要求收进左侧导航/内容区）；
- 搜索不是终点，我们需要“来源篮、加入候选、生成任务单”。

### 2.2 36氪首页

证据：`36kr-home.png`

观察：

- 顶部是媒体品牌/服务导航；
- 左侧是品牌区 + 一级/二级栏目（首页、快讯、资讯、直播、视频、专题等）；
- 中间是头条大图 + 文章流；
- 右侧是最新快讯、推荐直播等辅助信息；
- 整体是“内容门户”结构：品牌入口、栏目、信息流、右侧栏。

可借鉴：

- 左侧导航承载多层级内容，符合用户“直接集成在左边”的要求；
- 中间主内容 + 右侧辅助栏的布局；
- 栏目化组织，适合多行业内容。

不照搬：

- 不复制大图头条、营销位、活动位；
- 我们不是资讯门户，主任务是“搜索/选题/写稿”，不是“读文章”；
- 不做满屏推荐位，避免把工具做成媒体首页。

### 2.3 新榜首页

证据：`newrank-home.png`

观察：

- 顶部是产品/服务导航，右侧登录/企业应用；
- 左上排行榜、主区产品入口、右侧工具卡；
- 信息密度高，营销/产品入口多，偏“数据平台官网”。

可借鉴：

- 左侧栏放榜单/导航，符合专业工具习惯；
- 数据与工具入口分组清晰。

不照搬：

- 首页式营销模块、推广卡太多；
- 我们的首屏必须是搜索，不是产品介绍。

## 3. 综合结论：我们采用“搜索优先的独立门户”

不是纯 Bing（没有导航），也不是纯 36氪（内容门户），而是：

> **左侧主导航 + 顶部轻量工具 + 搜索优先的内容区 + 右侧辅助栏**

### 页面骨架

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部工具条（不吸顶、不是二级导航）                           │
│  工作室名            当前 IP   教程/帮助  配额  账号         │
├──────────┬──────────────────────────────────┬──────────────┤
│ 左侧导航  │ 主内容                            │ 右侧辅助栏    │
│ 240px    │ 最大 1120px                       │ 280px        │
│          │                                  │              │
│ 工作台    │ 页面标题/说明（随内容滚动）        │ 来源篮        │
│ 找选题    │ 搜索框 + 内联筛选                 │ 配额/说明     │
│ 选题库    │ 结果列表                           │ 相关操作      │
│ 研究      │                                  │              │
│ 创作流水线│                                  │              │
│ 来源库    │                                  │              │
│ 监控      │                                  │              │
│ 帮助/教程 │                                  │              │
└──────────┴──────────────────────────────────┴──────────────┘
```

约束：

- 页面内不再出现第二条置顶导航；
- 顶部工具条只放轻量操作，不承担栏目导航；
- 主内容全部有独立 URL；
- 不使用抽屉承载主内容。

## 5. 搜索页详细规范

### 5.1 尺寸与对齐

- 内容区最大宽度 1120px；
- 结果列 720–760px，右侧辅助栏 280px；
- 左侧导航 240px，固定；
- 页面左右留白 32px；
- 搜索框高度 48px，字号 15px，圆角 10px；
- 搜索按钮与输入框同高，按钮不抢视觉；
- 筛选行高度 36px，位于搜索框下方 12px；
- 结果条目间距 24px，分隔线 1px 极浅。

### 5.2 结果条目结构

```text
[favicon] 来源站点 · 域名 · 2026-11-05        [权威标签]
标题（最多两行，18px/600）
摘要（最多三行，14px/1.6，截断）
[查看原文] [加入来源篮] [复制引用]
```

固定信息顺序，不随机换位。

### 5.3 筛选

- 时间：不限/1天/7天/30天；
- 权威度：仅权威/较权威/全部（默认仅权威）；
- 站点：全部/政府/央媒/行业媒体（具体范围随行业包）；
- 类型：网页（首期）；图片（后续）；
- 排序：相关度/时间；
- 筛选为内联行，不做吸顶横条。

### 5.4 状态

- 初始：说明“输入关键词，找选题/查资料”；
- 加载：结果骨架屏；
- 无结果：建议换更短关键词/放宽时间/降低权威度；
- 错误：显示稳定 code + 可重试；
- 配额不足：显示剩余/重置时间；
- 未登录：登录引导。

### 5.5 搜索页右侧辅助栏

- 来源篮：已选来源数、权威度分布；
- “生成任务单”按钮（≥2 条来源可用）；
- 本次检索消耗说明；
- 不做推荐广告/热门榜。

## 6. 帮助/教程与案例

- 入口：顶部工具条右上角“使用教程”；
- 独立页面 `/studio/help`，不使用抽屉；
- 三个标签：快速开始 / 功能说明 / 案例库；
- 每篇 1–3 分钟，配真实截图；
- 功能旁“?”链接到对应章节；
- 案例：真实搜索/真实来源/人工修改，标注“演示案例”，不编涨粉/播放数据；
- 案例可一键“照着做”，带入关键词。

## 7. 与当前实现的差距

| 项目 | 当前 | 目标 |
|---|---|---|
| 页面归属 | 主站 `/topics`，跟主站主题 | 独立 `/studio`，独立主题 |
| 导航 | 顶部品牌 + 工作区栏 | 左侧主导航 + 顶部轻量工具 |
| 搜索位置 | 详情页研究标签底部 | 独立搜索页，首屏 |
| 搜索结果 | 长正文卡片 | 行式结果 + 来源/时间/权威度 |
| 来源 | 不持久化 | 来源篮 + 来源库 |
| 教程 | 无 | 独立帮助页 + 案例 |
| 内容生产 | 交接文案智能体（纯文本预填） | 任务单 + 口播 + 核查 + 版本 |
| 监控 | 无 | 关键词监控 + 问题追踪 |
