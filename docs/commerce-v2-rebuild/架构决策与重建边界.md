# 带货 Agent v2 架构决策与重建边界

更新时间：2026-09-26  
状态：本地重建中，未切换 `/commerce`，未部署，未触发付费生成

## 1. 决策

带货 Agent 采用隔离重建，主站其他功能保持原样。新实现先挂载在 `/commerce/rebuild`，旧 `/commerce` 仅作为行为证据和回滚入口。只有新核心通过确定性合同、构建、桌面与 390px 浏览器验收，并完成两个相邻页面回归后，才允许原子切换 `/commerce` 路由。

重建不等于丢弃所有既有实现。经过合同测试的底层能力，例如身份鉴权、媒体字节校验、资产原子落盘、模型目录读取、视频分段算法和供应商适配器，可以通过窄适配层复用。旧工作台组件、页面状态、静态模型筛选、客户端计价和互相修改全局配置的写法不得进入新核心。

## 2. 为什么重建更快

旧 Commerce 已形成大量页面和服务文件，但核心工作台仍将素材、模型、弹窗、编导、报价和任务状态混在同一客户端状态中。继续修补会重复解决以下问题：

1. 模型弹窗与当前素材、时长、画幅、清晰度、声音要求没有共用一份能力合同；
2. 本地临时文件、已持久化资产和生成资产身份混用；
3. 编导回复、可应用脚本和最终视频任务之间缺少强版本绑定；
4. 报价、模型配置、提示词版本与确认时刻可能漂移；
5. 页面刷新后，草稿、任务、声音应用和错误恢复状态不完整；
6. 工作台设置存在影响全局模型启用状态的风险；
7. UI 中出现按钮不等于后端链路已经闭环。

隔离重建把这些约束放入服务器合同和状态机，前端只消费同一事实源。这样新增图片、视频、声音、数字人或商详能力时复用同一生产骨架，不再复制一套弹窗和状态。

## 3. 不可越界范围

- 仅写 `src/commerce-v2`、`src/app/api/commerce/v2` 和 `src/app/commerce/rebuild`，切换阶段才窄改 `/commerce` 入口。
- 不修改自媒体操盘手、优采、画布、封面、声音工作台、数字人等非 Commerce 页面。
- 不用工作台请求写模型池的 `enabled`、渠道密钥、成本或全局默认路由。
- 不读取或返回供应商密钥、编译后的系统提示词、成本价和内部轮询地址。
- 不把镜像客户端代码当成私有服务端源码；镜像只作为路由、字段、状态和交互证据。
- 部署、生产写入和真实付费生成保持暂停。

## 4. 单一生产合同

```text
ProductionDraft/v2
  ├─ 素材身份与职责
  ├─ 编导目录/提示词/应用版本
  ├─ 模型能力快照
  └─ 图片或视频设置
          ↓
ProductionPlan/v2 + planHash
  ├─ 配置问题
  ├─ 执行问题
  ├─ 原生/动态分段
  └─ 尾帧续接责任
          ↓
ProductionQuote/v2
  ├─ planHash
  ├─ modelConfigHash
  ├─ 单价、计费单位和数量
  └─ 过期时间
          ↓ 用户明确确认
ProductionTask
  confirmed → queued → running → saving → succeeded
                              ↘ unknown / failed / save_failed
                                           ↓
                                  恢复、保存重试或退款
```

确认报价时必须同时核对计划哈希、模型配置哈希、金额和有效期。任一变化都要求重新报价。任务执行使用确认时的不可变快照，不从当前工作台重新读取设置。

## 5. 版本化身份

| 对象 | 稳定身份 | 不可变版本证据 |
| --- | --- | --- |
| 草稿 | `draft.id` | `revision` + 草稿协议版本 |
| 编导 | `skillKey` | `registryVersion` + `promptVersion` + `outputProtocol` |
| 模型 | 模型目录 ID | `configHash` + 已验证时间 |
| 生产计划 | `planId` | 服务器 `planHash` |
| 报价 | `quoteId` | `planHash` + `modelConfigHash` + `expiresAt` |
| 任务 | `taskId` | 确认时完整快照 + 单调状态事件 |
| 资产 | `assetId` | 所有者 + 字节大小 + SHA-256 + 媒体类型 |

编导提示词只在服务器装载。浏览器得到名称、用途、素材槽位和版本，不得到系统提示词正文。

## 6. 长视频合同

- 总时长只接受 4–80 秒。
- 模型原生支持目标时长时只创建一个片段。
- 非原生时长仅在模型明确声明支持滚动续接时进行精确分段。
- 第二段起必须引用上一段真实生成结果的尾帧，不能用首图或客户端占位图冒充。
- 参考图容量必须为尾帧额外预留一个位置。
- 30/60/70/80 秒在确定性夹具中的计划分别为 `15+15`、`15×4`、`14×5`、`14+14+13+13+13+13`。
- 临时尾帧属于任务临时资产；成功、失败和退款终态都必须进入清理流程。

## 7. 配置与持久化

- 工作台草稿按鉴权所有者派生的 `workspaceKey` 隔离保存。
- 浏览器选择态只影响当前草稿，不写全局模型池。
- 本地上传必须先变成服务器资产并获得 `assetId`，才能进入可报价计划。
- 服务器逻辑配置和密钥分离：公共目录仅返回能力与公开价格；凭据仍由服务端环境或密钥引用解析。
- 提示词、模型路由、模型目录和工作台分配使用各自版本，发布时由一个发布清单绑定；不允许局部写入制造混合版本。
- 导入配置必须先生成差异预览，发布使用原子切换，并保留可读回和回滚的上一版本。

## 9. 切换门禁

1. 每条可见操作都有对应 API、持久化、错误态和恢复态；
2. 19 编导都能形成版本化脚本并应用到同一生产合同；
3. 图片、视频、声音和数字人模型按真实能力筛选；
4. 30/60/70/80 秒计划和尾帧续接合同通过；
5. 报价、确认、任务、资产、历史、失败恢复和计费终态可读回；
6. 类型检查、确定性合同和零费用回归通过；
7. 当前 F 盘构建 `runningLatest=true`；
8. `/commerce/rebuild` 桌面与 390px 验收通过，并回归两个未修改页面；
9. 仅在上述条件满足后切换 `/commerce`；旧实现保留一个可回滚版本周期。
