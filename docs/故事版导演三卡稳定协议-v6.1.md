# 故事版导演三卡稳定协议 v6.1

## 结论

v6.1 不精简、不重写三张故事版导演的创作核心。迁移从数据库现有 `system_prompt` 中定位唯一的 `# 固定输出格式`，保留角色资产、口播转故事、语义包装、10种风格、画面方法和导演差异，只精确替换其中“面板数等于切镜数”的错误句，再升级输出尾段与后台预设字段。

只读验证结果：

| 智能体 | 当前字符 | 核心区字符 | 核心区占比 |
| --- | ---: | ---: | ---: |
| 高能夸张 | 5,190 | 4,761 | 91.7% |
| 电影叙事 | 5,194 | 4,765 | 91.7% |
| 抒情情感 | 5,198 | 4,769 | 91.7% |

原样保留的核心至少包括：

- 全片资产锁定；
- 口播转故事方法；
- 语义包装推导；
- 10 种 3D 风格执行字典；
- 4至5格故事板生图方法，仅修正版式判定；
- 图生视频“怎么演”的动作方法；
- 原质量门和三种导演差异。

## 输入协议

版本：`storyboard_director_input.v1`

稳定字段：

1. `segmented_script`
2. `animation_style`
3. `aspect_ratio`
4. `special_notes`

兼容旧字段：

- `storyboard_segmented_copy`
- `storyboard_visual_style`
- `storyboard_aspect_ratio`
- `storyboard_character_setting`
- `storyboard_special_requirements`

旧角色设定与旧特殊要求统一归入 `special_notes`。显示名称和排列顺序可以调整，稳定 ID 不变。

动画风格仍使用现有、已经写入导演提示词执行字典的 10 个选项，不改为简化版名称。

## 输出协议

版本：`storyboard_director_output.v1`

每个原文段落先输出两个独立标准 Markdown `text` 代码框：

1. `storyboard_image_prompt`：生图 Prompt；
2. `image_to_video_prompt`：图生视频 Prompt。

所有段落结束后输出一个 `json` 机器包。机器只按以下稳定字段读取，不依赖标题和代码框位置：

```json
{
  "schema_version": "storyboard_director_output.v1",
  "artifact_type": "storyboard_director_package",
  "director_mode": "high_energy | cinematic | lyrical",
  "input": {
    "schema_version": "storyboard_director_input.v1",
    "segmented_script": "",
    "animation_style": "",
    "aspect_ratio": "16:9",
    "special_notes": ""
  },
  "segments": [
    {
      "segment_id": "segment_001",
      "source_index": 1,
      "narration": "",
      "panel_count": 4,
      "layout": "two_by_two",
      "pacing_mode": "medium",
      "actual_shot_count": 3,
      "panoramic_anchor_role": null,
      "character_assets": [],
      "semantic_visualizations": [
        {
          "trigger": "",
          "visual_form": "",
          "interaction": ""
        }
      ],
      "storyboard_image_prompt": "",
      "image_to_video_prompt": ""
    }
  ]
}
```

### 4–5格自适应

- `panel_count=4`：语义只有四个有效视觉节拍，或不存在独立宽幅锚点；`layout=two_by_two`，`panoramic_anchor_role=null`。
- `panel_count=5`：只有高潮、结论、警示揭示、空间全貌或情绪收束值得独立宽幅表现时使用；`layout=four_plus_panorama`。
- 五格 Prompt 必须包含 `top four panels in a 2x2 grid, bottom Frame 5 full-width panoramic panel`。
- 禁止为了版式硬凑第五格、上2下3等宽、五张独立图或错序拼贴。

### 面板与镜头解耦

五个面板是视觉素材与动作覆盖，不等于五次切镜。`pacing_mode` 按情绪、信息密度和动作强度选择 `slow | medium | fast`；约10秒视频的 `actual_shot_count` 为：

- 高能夸张：2–4镜头；
- 电影叙事：2–3镜头；
- 抒情情感：1–2镜头。

普通段落默认2–3镜头，每镜约2.5–5秒。视频 Prompt 必须按实际镜头写明时长、镜内表演、运镜与物理反馈，不得按 Frame 逐格强切。

## 执行门禁

必须通过 PostgreSQL 直连或受控事务 SQL 执行器，以 `ON_ERROR_STOP` 方式在单事务内执行。不得用 Supabase REST 的多次 HTTP 请求代替事务。
