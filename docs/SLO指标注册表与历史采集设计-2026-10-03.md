# SLO 指标注册表与历史采集设计（2026-10-03）

## 当前审计结论

- `admin-command-center` 当前共有 **41 项**真实指标：会员 3、资金 7、生产任务 4、模型 4、安全 4、系统运行 5、治理闭环 14。
- 指挥中心是有界即时读取模型，已有 `definitionVersion`、来源覆盖率、新鲜度、部分覆盖和不可用语义，但此前没有统一登记每项指标的负责人、公式、分子分母、排除规则、查询版本和阈值。
- `incident_slo` 已有控制面基础表；服务端状态仍明确写着 `collectorsConnected=false`。它不是这 41 项指标的历史采集器，不能用空测量推导“0 个事故”或“全部健康”。
- `operation_flight_events`、`health_checks` 和 `system_logs` 是现有事实源；它们各自的事件、诊断和日志语义不同，不能互相替代。

## 已建立的功能链

1. `src/lib/slo-metric-registry.ts` 对 41 项指标逐项登记：稳定 ID、中文名、业务目标、负责人、公式、分子、分母、单位、粒度、排除规则、数据源、查询版本、告警阈值、新鲜度目标和下钻地址。
2. `src/lib/server/slo-metric-registry.ts` 按六个功能目标读取当前指挥中心快照，并把当前值分成 `available / partial / unavailable`。缺值或来源失败保持 `null + unavailable`，真实的数值 0 仍是可用值。
3. `GET /api/admin/slo-metrics/registry` 只读、`no-store`，需要指挥中心完整权限集。服务端有 60 秒短缓存、同键 singleflight、手动刷新 60 秒冷却和 `429 + Retry-After`。
4. `SloMetricRegistryPanel` 只在证据视图按需挂载；页面隐藏、浏览器离线时中止读取，恢复后只在快照过期时继续。自动读取间隔为 5 分钟，使用一次性定时器，没有 `setInterval`。
5. `POST /api/internal/slo-metrics/capture` 只接受独立服务身份：功能开关、32 字符以上共享密钥、五分钟时间戳、HMAC-SHA256、幂等键和进程内最低频率。管理员 Cookie 不能触发采集。
6. `scripts/capture-slo-metric-snapshot.mjs` 默认只打印零网络、零写入计划；必须显式加 `--execute` 才会发起签名请求。

## 历史持久化当前边界

`docs/design-sql/admin-slo-metric-history-v1.sql` 只是 **design-only** 设计，未放入 `supabase/migrations`，本任务也没有应用数据库迁移。当前 UI/API 必须显示：

- 历史持久化：不可用；
- 原因：`HISTORY_MIGRATION_NOT_APPLIED`（真实数据库缺表时）；
- 趋势点：空数组，但不绘制 0 折线；
- SLO 采集器：未接入；
- 当前 41 项值：仍可来自有界实时读取，和历史持久化状态分开。

设计 SQL 提供原子 RPC `capture_admin_metric_snapshot`，一次写入 run 与最多 100 项 value；`capture_key` 唯一，同键同载荷返回原回执，同键不同载荷拒绝。两张表启用 RLS，只向 `service_role` 开放。该 SQL 后续必须经过隔离数据库迁移、双次幂等验证和回滚审计后，才能转为正式迁移。

## 低成本运行建议

- 当前页面自动读取：5 分钟；手动刷新：每管理员至少 60 秒；服务缓存：60 秒。
- 独立历史采集建议从 5 分钟起步。页面 GET 永远不写快照，避免每个管理员打开页面都放大数据库写入。
- 单次读取最多 6 个目标视图、24 个历史 run、984 行历史值；默认只取 12 个 run、492 行值。
- 历史保留期在业务确认前不自动删除；后续应由独立维护任务做分层保留，例如 5 分钟点保留 7 天、小时点保留 90 天、日点保留 2 年。

## 上线门禁

1. 将 design SQL 转成带时间戳的正式迁移并在隔离数据库应用。
2. 使用相同幂等键执行两次签名采集，证明只有 1 个 run 和 41 个 value。
3. 验证不同载荷复用同键得到冲突；过期时间戳、错误签名、浏览器 Cookie 均被拒绝。
4. 配置独立调度器与密钥轮换，不把密钥写入前端或仓库。
5. 在 1440×900 最终构建上验证注册表、筛选、展开、隐藏/离线暂停、429，以及相邻健康/总览页。
6. 只有当历史表、采集器和至少两个真实时间点都通过后，才把“历史趋势”从不可用改为已接入。
