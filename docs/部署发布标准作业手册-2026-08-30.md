# 自媒体操盘手 · 部署发布标准作业手册

更新时间：2026-09-01
适用事实源：`F:\总项目文件\Skill存储系统\01_网页开发项目\自媒体操盘手\当前版本`

## 1. 总原则

本项目以后按“代码、数据库、对象素材、运行态数据”四条链路分离发布。

| 链路 | 是否进入 Git | 是否可直接覆盖服务器 | 标准做法 |
| --- | --- | --- | --- |
| 源代码、配置模板、迁移、测试脚本 | 是 | 可以覆盖代码目录 | 本地当前版本验证通过后同步到干净发布仓，再由服务器拉取精确 commit 或接收构建产物 |
| 数据库结构迁移 | 是，只保存 migration SQL | 不覆盖 | 发布前备份数据库，按迁移计划哈希执行 forward-only 迁移 |
| 会员、订单、余额、生成记录、业务数据 | 否 | 禁止覆盖 | 只在数据库中演进；通过备份、迁移和恢复演练保护 |
| 上传素材、用户媒体、生成结果 | 否，不进源码仓 | 禁止覆盖 | 生产使用 COS/对象存储 + CDN；服务器只保留临时缓存或挂载目录 |
| 公共演示素材、官网静态图标、无密样例 | 是 | 可以随构建覆盖 | 放在 `public/`，由 release manifest 校验 |

核心判断：Git 是“代码版本证据”，不是数据库备份，也不是用户素材仓库。

## 2. 为什么之前部署容易失败

当前项目已经有大量功能模块：漫剧工作台、自由画布、Skill 专家、计费、生成记录、语音、视频、素材库。失败不是单点问题，而是三类链路没有完全闭环：

1. 本地源代码已经增加了表、RPC、配置中心和素材协议，但生产数据库 schema 没有同步到同一版本，页面只能降级到“内置安全兜底”。
2. 部署时没有固定“先备份 → 迁移 → 验证 schema → 构建 → 上传/覆盖 → 健康检查”的顺序，容易出现代码已更新、数据库没更新。
3. 素材没有完全从代码里解耦：公共演示素材可以跟代码走，后台上传/用户素材必须走对象存储和数据库登记，不能硬写在前端组件里。

所以以后不能只问“推 Git 成功了吗”，要问四个状态是否一致：

- Git commit 是否是本地验收过的 commit；
- 数据库 schema 是否达到 `deploy/policies/database-contract.v1.json`；
- 静态公共素材 manifest 是否完整；
- 服务器运行的 build ID 是否等于发布的 build ID。

## 3. 本地开发与保存标准

本地唯一事实源：

```text
F:\总项目文件\Skill存储系统\01_网页开发项目\自媒体操盘手\当前版本
```

日常开发只改这个目录。当前版本本身就是 Git 工作区，提交与发布只从这里产生；不允许用远端 Git 反向 `pull/reset` 覆盖本地事实源。

每次较大修改至少保留：

- `.codex-backups/<任务名-时间>/manifest.json`：改动前目标文件 SHA-256；
- `.codex-evidence/<验收名-时间>/report.json`：改动后验证证据；
- 文档或 LOG 记录：说明本次改了哪些功能域。

## 4. 数据库迁移标准

迁移 SQL 只放：

```text
supabase/migrations/*.sql
```

回滚 SQL 只放：

```text
supabase/rollbacks/*.sql
```

禁止把 rollback/down 文件放进 forward migration 目录。

新增标准命令：

```bash
pnpm deploy:db:verify
pnpm deploy:db:plan
pnpm deploy:db:status
pnpm deploy:db:apply
```

`plan/status` 默认不写库。`apply` 必须同时满足：

- 已完成迁移前数据库备份；
- 指定数据库连接环境变量，例如 `DEPLOY_DATABASE_URL`；
- 确认目标 host；
- 确认 plan 生成的 manifest SHA-256；
- 提供备份回执或备份路径。

PowerShell 示例：

```powershell
$env:DEPLOY_DATABASE_URL = "<从密码管理器读取，不写入仓库>"
pnpm deploy:db:plan
pnpm deploy:db:apply -- --confirm-target-host=<database-host> --confirm-manifest-sha256=<plan-manifest-sha256> --confirm-backup=<backup-receipt-or-path>
pnpm deploy:ready
```

Linux/服务器示例：

```bash
export DEPLOY_DATABASE_URL='<从服务器安全环境变量读取>'
pnpm deploy:db:plan
pnpm deploy:db:apply -- --confirm-target-host=<database-host> --confirm-manifest-sha256=<plan-manifest-sha256> --confirm-backup=<backup-receipt-or-path>
pnpm deploy:ready
```

重要：应用运行时不自动迁移数据库。迁移必须作为发布流水线的一步执行。

## 5. 素材存储标准：推荐 COS + CDN

生产环境推荐：

```text
用户上传素材 / 生成结果 / 后台上传素材 → COS 对象存储 → CDN 加速 → 数据库登记元数据
公共演示素材 / 官网静态图 → public/youcai-media → release manifest → CDN 或服务器静态文件
```

原因：

- 服务器硬盘适合运行代码，不适合长期承载大量图片、视频和生成结果；
- COS/CDN 能显著降低首屏和瀑布流图片加载压力；
- 数据库只保存素材记录、归属、用途、状态、checksum、URL/key，不保存大文件本体；
- 部署代码时不会覆盖用户素材和会员数据。

如果短期先用服务器硬盘，也必须满足：

- 上传目录挂载到 `shared/uploads`；
- `public/uploads` 只能作为运行时挂载或反向代理目标，不能随代码包覆盖；
- Nginx 单独配置 `/uploads/` 静态路径；
- 每次部署排除 `shared/uploads`、`shared/data`、`shared/backups`。

## 6. 漫剧工作台后台标准

漫剧工作台是独立产品页，不属于主站 Skill 应用广场的卡片堆。

后台应分成三层：

1. 漫剧工作台配置中心：配置首页文案、导航、Banner、功能入口、前台展示素材、画布示例、feature flags。
2. 内置 Skill 治理：管理员可以修改平台内置 Skill 的提示词覆盖、发布覆盖、恢复默认，但普通用户不能编辑内置 Skill 本体。
3. 用户自建 / 导入 Skill 包：用户或管理员创建自己的 Skill，支持草稿、校验、发布、安装、回滚；这条链路依赖 `skill_packages` 相关数据库迁移。

前台消费规则：

- 前台只读“已发布/已生效”的配置；
- 后台草稿不直接污染前台；
- 后台上传素材必须生成数据库记录；
- 前台素材失败时要显示可理解的降级信息，但不能冒充素材已发布成功。

## 7. Git 发布仓标准

Git 发布仓只保存：

- 源代码；
- `package.json` / `pnpm-lock.yaml`；
- `supabase/migrations`；
- `deploy/` 策略与 manifest；
- `docs/` 标准作业手册；
- 无密 `.env.example`。

Git 发布仓不保存：

- `.env.local` / `.env.production`；
- 数据库导出；
- 用户上传文件；
- 真实 API Key / Token / Cookie；
- `.next` 构建产物，除非未来明确改为 artifact 仓库。

发布仓必须有：

- `origin`：主私有仓；
- `backup`：独立备份仓，不能和 origin 同一宿主；
- 受保护 `main`；
- 每次部署记录 commit hash。

当前如果只有本地 `local-archive`，只能算本地发布归档，不算生产级 Git 闭环。

## 8. 服务器覆盖策略

用户希望“直接覆盖”，可以采用，但必须是受控覆盖：

允许覆盖：

- 应用源代码；
- 构建产物；
- `deploy/nginx/*.example`、`deploy/pm2/*.cjs` 这类发布模板。

禁止覆盖：

- `.env.production`；
- `shared/data`；
- `shared/uploads`；
- `shared/assets/current` 指向的线上素材；
- 数据库；
- 日志与备份。

推荐顺序：

1. 服务器上保留当前可运行版本快照；
2. 上传或拉取新 commit；
3. 安装依赖用 lockfile 冻结；
4. 不在服务器临时改源码；
5. 启动前确认数据库 readiness；
6. PM2 reload；
7. 验证 `/api/version`、`/api/release-readiness`、核心页面；
8. 若失败，回滚代码目录快照，数据不回滚，除非数据库迁移另有回滚方案。

如果未来追求更高可靠性，推荐改成不可变 release 目录 + symlink 原子切换；如果当前阶段为了简单，直接覆盖也必须保留“覆盖前快照 + shared 目录不动 + 健康检查失败回滚”。

## 9. 发布模式

| 模式 | 适用情况 | 是否全量覆盖代码 | 是否迁移数据库 | 是否处理素材 |
| --- | --- | --- | --- | --- |
| CODE | 小功能、小 UI 修复 | 是 | 否，除非 schema 变更 | 否 |
| DB | 后台保存失败、缺表/缺 RPC | 否 | 是 | 否 |
| ASSET | 公共素材替换、静态示例更新 | 否或少量 | 否 | 是 |
| FULL | 大功能迭代、漫剧工作台这种跨前后端变更 | 是 | 是 | 是 |

漫剧工作台本次属于 FULL：前端、后台、数据库、素材示例、Skill 生命周期都有关联。

## 10. 部署前验收门禁

部署前至少通过：

```bash
pnpm deploy:db:verify
pnpm deploy:db:plan
pnpm deploy:ready:code
pnpm build
pnpm start
pnpm deploy:ready
```

`deploy:ready:code` 通过只代表源码、配置、发布仓结构达到代码门禁；`deploy:ready` 通过才代表生产 schema、发布仓远端、运行预览也到位。

本项目禁止把以下结果当作完成：

- 只看到页面 200；
- 只看到浏览器打开；
- 只通过静态检查；
- 只推送本地 Git；
- 只显示“内置安全机制”；
- 配置中心实际不可保存；
- 素材卡片显示但图片加载失败。

## 11. 本次发布最低交付标准

漫剧工作台要上线，至少满足：

- 后台配置中心不再出现 `CONFIG_STORE_CORRUPT`；
- 内置 Skill 36 张卡片在后台可见，并支持管理员覆盖提示词、发布、恢复默认；
- 用户自建 / 导入 Skill 包入口可见，schema ready 后可保存草稿、发布、安装、回滚；
- 后台素材可上传、编辑、软删除，并能映射到前台素材流；
- 前台 `/youcai`、`/youcai/skills`、`/youcai/tools/canvas` 正常加载；
- 自由画布示例能查看、复制、进入编辑；
- 所有核心导航页面无 5xx、无配置腐败横幅；
- 发布仓 commit 和运行 build ID 可追溯。

未达成上述标准，不进入正式服务器覆盖。
