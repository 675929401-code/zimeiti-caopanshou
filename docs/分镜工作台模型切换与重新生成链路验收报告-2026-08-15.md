# 分镜工作台模型切换与重新生成链路验收报告

日期：2026-08-15  
范围：`/storyboard-workbench` 单卡生图、单卡视频、模型切换、重新生成、失败重试、终止、历史恢复。  
费用：0；全部使用本地会话与浏览器 Mock，未调用真实生图或视频模型。

## 根因

1. 视频重新生成时没有立即清空旧 `videoUrl`。组件优先渲染旧视频，因此新任务虽然可能已经提交，用户仍看到旧结果，表现为“点击没反应”。
2. 视频进入公网存储迁移时，运行状态设置得太晚。迁移期间没有即时反馈。
3. 批量流程未结束时，单卡按钮被全局禁用，且没有解释；已完成卡片也无法单独重新生成。
4. 重复提交锁直接返回，没有状态提示。
5. 重新生图会改变视频首帧，但旧视频任务、URL和进度字段没有完整按同一事务语义失效；运行中的视频还可能反向写回旧结果。
6. 生成失败只写卡片错误，底部全局状态没有同步说明。
7. 历史列表按同一运行 ID 覆盖，重生成前的成功结果无法作为独立快照恢复。

## 修复

- 视频提交前立即展开结果区、进入排队态、清空旧视频并显示所选模型。
- 生图和视频请求均从同步更新的 `runRef` 读取当前模型；模型选择后明确提示“下一次生成将使用该模型”。
- 重新生图完整失效下游视频 URL、任务 ID、模型 ID、进度、计时和错误；视频运行中禁止重新生图并给出原因。
- 生图/视频成功、失败、余额不足、审核失败、终止均同步到卡片和全局状态条。
- 重复点击不再静默，明确提示请求已经提交。
- 失败按钮显示“重试生图/重试生成”，终止后显示“重新生成”。
- 批量任务中，已完成且不在当前待提交队列的卡片可单独重新生成；批量异常使用 `finally` 释放全局锁。
- 每次覆盖已有图片或视频前生成独立本地历史快照，保留旧媒体和 Prompt，可从历史恢复。
- 卡片标记最近一次故事板实际使用的图片模型，避免把当前全局选择误认为旧结果的生成模型。

## 无费用端到端验收

脚本：`scripts/verify-storyboard-regeneration-ui.mjs`

通过项：

- GPT Image A 切换到 Gemini Image A 后重新生图，请求体实际为 `img-gemini`。
- 生图切回 GPT 后模拟失败，再切 Gemini 重试成功，请求顺序为 `img-gemini -> img-gpt -> img-gemini`。
- 重新生图后旧视频立即清空，视频状态回到 `idle`。
- Video Alpha / Video Beta 切换后，请求顺序为 `vid-beta -> vid-alpha -> vid-beta -> vid-alpha`。
- 视频重新生成期间旧 `<video>` 不再显示；失败后可重试并使用最新模型。
- 视频生成中点击重新生图不会破坏参考图链路，必须先终止视频。
- 图片和视频覆盖前均写入可恢复历史快照。
