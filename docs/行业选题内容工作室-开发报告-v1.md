# 行业选题内容工作室 · 开发报告 v1

- 文档性质：开工前定稿（本报告通过后才进入实现）
- 编写时间：2026-11-09
- 依据：火山引擎豆包搜索官方文档与控制台能力、平台现有账号/积分/智能体能力、用户补充要求
- 当前状态：仅本机方案设计；未部署、未改生产、未接自动发布

---

## 1. 结论摘要

做一套**独立于主站视觉与导航的「AI 内容工作室」**，不是主站里的又一个页面。

它解决四件事：

1. 用豆包搜索把“公开互联网”变成可核查的选题与资料；
2. 用行业包适配宠物/美妆/科技等不同行业，不为单一赛道定制；
3. 用智能体流水线把资料变成**有引用、可核查、符合 IP 人设的口播内容**；
4. 用候选池、监控、问题追踪和发布复盘形成闭环。

核心边界：

- 只做官方文档定义的搜索能力，不发明“热榜、账号监控、自动生成行业报告”；
- 外部结果一律标注“未审核”，不自动发布；
- 不存全文、不洗稿、不伪造来源/期号/作者/热度；
- 搜索 API Key 只存服务端，不进前端、不进日志、不进仓库。

---

## 2. 背景与要解决的问题

现状：

- 行业选题页已有 12 条站内示例、研究分析、创作草稿与文案智能体预填；
- 联网检索已从“未开通”推进到能真实调用豆包搜索；
- 但仍是“搜完就结束”：没有来源存档、候选池、口播生产、监控与复盘；
- 之前用“第 01 期/第 02 期”和“平台编辑部”包装示例，已确认是错误设计并移除。

用户要的最终结果不是“搜索框”，而是：

> 找到一个赛道/选题 → 有权威依据 → 变成自己的口播内容 → 发布 → 持续跟踪 → 下一轮。

同时要求：

- 多行业用户共用一套能力；
- 界面独立，不跟随自媒体操盘手主页主题；
- 无二级页面置顶横条，导航直接集成在左侧；
- 搜索页的信息层级、对齐、留白、状态要像大厂搜索产品，而不是卡片堆叠的活动页。

## 3. 官方能力基线（只写文档/实测支持的内容）

### 3.1 豆包搜索提供的

- **输入**：`Query`（1–100 字自由文本）、`SearchType`（web/image）、`Count`、`TimeRange`、权威度过滤、站点/域名范围、行业/领域控制（以 API 参考逐项为准）。
- **输出**：标题、来源站点、URL、发布时间、摘要/正文、来源权威度、相关度、图片等。
- **计费/配额**：官方每月 500 次免费额度、默认 10 QPS，超出按套餐/后付费。
- **接入形态**：API Key + HTTP API；官方仅有控制台调试页、Postman/Python demo、方舟工具文档，**没有可直接套用的成品网站/前端模板**。

### 3.2 官方没有的（产品绝不能包装成官方能力）

- 没有“热榜/热度值/阅读量”；
- 没有抖音/小红书账号库、粉丝数、作品数据；
- 没有“一键行业报告”“自动选题”“自动写稿”；
- 没有公开可访问的客户案例网站/前端模板；
- 搜索结果未经审核，不代表真实、及时、无版权风险。

### 3.3 能力证据等级

| 能力 | 证据等级 | 当前状态 |
|---|---|---|
| Query / SearchType / Count | 官方文档 + 实测 200 | 可接 |
| TimeRange | 官方文档 + 实测一周过滤 | 可接，需 UI 验证 |
| AuthInfoLevel | 官方文档 + 实测 1 级结果明显更权威 | 可接，默认建议 1 |
| 站点/域名范围 | 文档提及，未逐项实测 | P1 再验证，未验证前不写进 UI 承诺 |
| 行业/领域参数 | 文档提及，未逐项实测 | P1 再验证 |
| 图片搜索 | 文档提及 | P2 评估，不默认开 |
| 正文/摘要/图片字段 | 实测返回 | 只做引用与展示 |
| 搜索总结/问答 | 官方另有产品形态 | 不纳入本期，避免混淆 |

## 4. 用户、角色与多行业模型

### 4.1 用户类型

- 个人博主：一个 IP，重选题和口播；
- MCN/工作室：多个 IP、编辑协作、审核；
- 行业专家：专业内容，强合规；
- 品牌内容团队：品牌安全、产品信息、投放素材。

### 4.2 角色权限

- Owner：IP、配额、成员、行业包；
- Editor：搜索、候选、写稿、提交审核；
- Reviewer：审核来源/事实/合规/发布；
- Viewer：只看，不可改。

> 遗漏补充：必须有“IP 级隔离”，不能一个账号下多个 IP 互相看到草稿；审核与发布分离。

### 4.3 行业包（不为单一行业定制）

行业包是配置，不是代码分支：

```text
industry_pack
- key / name
- 关键词模板
- 权威来源白名单/优先级
- 默认时间范围/权威度
- 合规红线与禁用表达
- 口播模板/结构
- 可用搜索能力（web/image/站点/行业）
- 内容形式与时长建议
```

首期：宠物、美妆、科技。  
新增行业：后台配置或种子文件，不改主流程。

### 4.4 IP 档案

- 行业/细分赛道；
- 目标受众；
- 人设/语气；
- 内容形式与时长；
- 商业目标（涨粉/带货/私域/品牌）；
- 禁用表达与合规要求；
- 视觉/口头禅/CTA；
- 绑定行业包。

同一来源、同一选题，不同 IP 生成不同口播。

## 5. 独立界面设计

### 5.1 站点边界

- 路由：`/studio`（独立布局）；
- 不加载主站 AppShell/主题变量/二级页置顶横条；
- 只复用登录身份与积分体系；
- 自己的一套颜色、字体、间距、圆角、动效；
- 固定浅色工作室风格，不跟随主站换肤。

### 5.2 布局

```text
┌──────────────┬─────────────────────────────────────────┐
│ 左侧导航 240  │ 内容区                                   │
│              │ 页面标题/说明（随内容滚动，不吸顶）        │
│ 工作台        │ 搜索栏 / 筛选 / 结果 / 来源篮 / 任务       │
│ 找选题        │                                         │
│ 选题库        │                                         │
│ 研究          │                                         │
│ 创作流水线    │                                         │
│ 来源库        │                                         │
│ 监控          │                                         │
│ IP 设置       │                                         │
│              │                                         │
│ 账号/配额     │                                         │
└──────────────┴─────────────────────────────────────────┘
```

- 左侧导航承担一级 + 当前模块入口；
- 页面内不再有第二条置顶导航；
- 详情用右侧抽屉或内容内联，不叠第三层导航；
- 面包屑只在内容区顶部，不吸顶。

### 5.3 搜索页：按大厂搜索产品的“对齐”标准做

不是做成活动卡片墙，而是：

- 主内容最大宽度 1120px，结果列 720–760px，右侧 280px 来源篮/配额；
- 搜索框高度 48px，字号 15–16px，圆角 10px，聚焦有清晰 ring；
- 搜索按钮与输入框同一基线，按钮不抢视觉；
- 搜索框下方是**内联筛选行**（时间/权威度/站点/类型/排序），不吸顶、不悬浮；
- 结果项统一网格：
  - 第一行：来源站点 + 域名 + 发布时间（12–13px，灰色）；
  - 第二行：标题（18px/600，最多两行）；
  - 第三行：摘要（14px/1.6，最多三行，超出截断）；
  - 右下或行尾：查看原文 / 加入来源篮 / 复制引用；
- 结果间距 24px，分隔线极轻；不用大面积阴影卡片；
- 右侧来源篮：已选来源数、权威度分布、去生成任务单；
- 空态/错误态/配额不足/未登录各有独立文案；
- 键盘：Tab 顺序、Enter 检索、Esc 清空、焦点可见；
- 对比度达到 WCAG AA；桌面 1440 验收，移动端不做。

### 5.4 搜索交互

- 不自动搜索，Enter/点击才发起；
- URL 保存关键词与筛选，刷新/返回可恢复；
- 每次搜索前显示“将消耗 1 次搜索配额”；
- 结果页固定显示“外部结果 · 未审核”；
- 默认权威度 1；用户可切“全部”；
- 不展示任何“热度/排名/爆款”指标；
- 不提供假联想词；意图模板必须经过实测。

### 5.5 首次引导

1. 选行业包；
2. 建 IP 档案（3 步内完成）；
3. 用示例词搜一次，展示“来源→加入来源篮→生成任务单”的下一步。

引导文案只解释“能做什么、不能做什么、消耗什么”。

## 6. 内容生产：从资料到口播

### 6.1 数据对象

- SearchSession：一次搜索（query/filters/results/quota）
- SourceItem：来源（标题/站点/URL/时间/权威度/短引用）
- TopicCandidate：候选选题（状态/行业/IP/来源/角度）
- Brief：创作任务单（结构化）
- ResearchNote：事实/观点/不确定项
- ScriptVersion：口播稿（版本/引用/合规结果）
- QAReport：核查报告
- StoryboardLink：分镜任务
- Publication：发布记录
- Feedback：播放/评论/复盘
- WatchKeyword / Finding：监控词与发现

> 只存来源元数据 + 短引用，不存全文；链接失效可标记，不复制正文。

### 6.2 流水线

```text
discovered → shortlisted → verified → briefed
→ scripted → checked → approved
→ storyboarded → produced → published → reviewed
```

任何一步都可退回；任何产物都有版本；不覆盖历史。

### 6.3 智能体分工（MVP 只做 3 个）

1. **研究智能体**：来源拆事实/观点/数据，标注 `[S1]`，列不确定项；
2. **口播编剧智能体**：按 IP 人设、时长、平台生成结构化口播稿；
3. **事实/合规智能体**：逐条核查引用、时间、绝对化、医疗/金融/广告风险。

后续再加分镜/封面/标题/配音智能体。

### 6.4 口播稿输入

- IP 档案；
- 选题/角度/受众；
- 2–3 条来源及关键句；
- 形式/时长/平台；
- 必引事实、禁说项、CTA。

### 6.5 口播稿输出（JSON）

```json
{
  "hook": "...",
  "why": "...",
  "points": [{"text": "...", "citation": "S1"}],
  "steps": ["..."],
  "boundary": "...",
  "cta": "...",
  "sources": [{"id": "S1", "title": "...", "url": "...", "site": "...", "publishedAt": "..."}],
  "riskNotes": ["..."]
}
```

### 6.6 生成硬规则

- 每个数字/结论/政策必须带引用；
- 无来源内容只能进“待核实”，不能写成事实；
- 禁止编造案例、用户评价、专家身份；
- 禁止绝对化、医疗诊断、收益承诺；
- 不整段复制来源；引用短句并给链接；
- 模型选择与计费走平台 `/api/llm`，一次用户确认一次调用，失败不自动重试；
- 生成后必须人工确认才能进分镜/发布。

### 6.7 与现有智能体的联动

- 选题页只出「任务单」，不内置完整聊天编辑器；
- 文案智能体负责口播稿；
- 脚本确认后送故事导演/分镜工作台；
- 封面/配音按需；
- 统一 `taskId`/`version`，产物回链到工作室；
- 交接只预填，不自动发送、不自动生成。

> 遗漏补充：需要“回传状态”——文案智能体生成后，工作室要看到“脚本 v1 已生成”，而不是用户自己找。

## 7. 闭环、监控与问题追踪

```text
找选题 → 选来源 → 候选 → 研究 → 任务单 → 口播稿
→ 核查 → 人工确认 → 分镜/封面/配音 → 发布
→ 回填数据/评论 → 复盘 → 关键词监控 → 下一轮
```

### 7.1 监控

- 关键词：行业词、竞品词、风险词；
- 频率：每日/每周，受 500 次/月配额约束；
- 只记录新结果：URL + 发布时间去重；
- 新结果进“候选收件箱”，人工审核后才成选题；
- 不自动发布、不自动改稿。

### 7.2 问题追踪卡

```text
问题 / 关键词 / 当前结论 / 已有来源
状态：待核实 / 已证实 / 有反转 / 已过时
下次复查时间
新来源提醒
```

### 7.3 发布复盘

- 首期手动回填：播放、完播、评论问题、涨粉；
- 评论问题转关键词；
- 复盘维度：选题来源、角度、口播结构、时长；
- 不伪造平台数据；平台 API 未接前只做手动。

## 8. 技术架构

- 前端：Next.js 独立路由组，独立 CSS token，不 import 主站主题；
- 后端：`/api/studio/*`，服务端持有搜索 Key；
- 搜索：固定官方端点，输入校验、超时、限流、错误码；
- 数据：Supabase 表 + RLS；迁移单独评审；
- 模型：复用平台 `/api/llm`，积分/幂等/计费不变；
- 任务：监控用受控定时任务，配额硬上限；
- 观测：requestId、失败码、耗时、配额消耗；日志不写正文/Key；
- 安全：外部网页内容一律当不可信数据，防提示词注入；链接只允许 http(s)，新窗口 noopener；
- 功能开关：搜索、监控、口播生成分别可关；默认最小开启。

## 9. 风险与合规

| 风险 | 处理 |
|---|---|
| 搜索结果不实/过期 | 权威度+时间筛选；至少 2 来源；原文核对 |
| SEO/营销稿 | 默认权威 1；显示站点；低质折叠 |
| 版权 | 只存元数据+短引用+链接，不存全文；图片需授权 |
| 医疗/金融/法律 | 行业包红线 + 合规智能体 + 人工审核 |
| 提示词注入 | 外部内容作为数据，不作为指令；系统提示隔离 |
| 配额/成本 | 500 次/月硬提示；监控预算；模型按次确认 |
| Key 泄漏 | 仅服务端 env；不返回前端、不写日志/仓库 |
| 自动发布风险 | 人工确认节点；默认关闭自动发布 |
| 多 IP 数据串 | IP 级 RLS 与权限 |
| 平台数据缺失 | 明确不提供账号数据，不用假指标补 |

## 10. 分期与验收

### P0 独立工作室 + 搜索

- 独立 `/studio`、左导航、固定主题；
- 行业包（宠物/美妆/科技）；
- IP 档案；
- 搜索页（时间/权威度/结果卡/来源篮/配额）；
- 来源存档。

验收：三行业各搜一次真实结果；无主站主题/二级横条；控制台 0 error；1440 截图；错误/空态/未登录/配额不足通过。

### P1 候选池 + 任务单

- 来源加入候选；
- 候选审核；
- 结构化 Brief；
- 来源/引用可追溯。

### P2 口播稿 + 核查

- 研究/口播/合规三个智能体；
- 引用清单、版本、人工确认；
- 失败/超时/空正文有明确状态。

### P3 智能体联动

- 任务单→文案智能体；
- 脚本→分镜；
- 状态回传；
- 封面/配音按需。

### P4 监控 + 复盘

- 关键词监控、新结果收件箱；
- 问题追踪卡；
- 手动发布数据回填。
