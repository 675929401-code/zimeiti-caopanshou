# 智能体提示词与模型配置维护说明

本文解释产品后台操作与数据边界，不替代项目工作台、交接回执或部署权威规约。当前运行身份与验收状态以实时查询及不可变回执为准。

## 提示词在哪里修改

F 盘 `当前版本/` 是唯一可编辑源码。提示词文件在本地完成修改和验收后，选定正文再保存到目标智能体配置；代码发布与提示词配置保存是不同动作。代码变更发布入口见[项目部署唯一规约](../../../../99_系统协议/02_操作协议/自媒体操盘手部署执行规约-当前版.md)，本文不另列部署步骤。

本地启动器支持两种数据模式：

- `local-acceptance`：提示词、模型目录与业务数据都使用本机隔离验收库。这里保存不会自动改变生产。
- `formal-local-shared`：在已正确配置共享 HTTPS 数据源、服务端凭据和配置身份后，列入共享范围的表从共享配置库读取。它不是通过模型 API 密钥自动建立的连接。

共享模式取决于 `SHARED_CONFIGURATION_ENABLED`、`SHARED_CONFIGURATION_SUPABASE_URL`、受控服务凭据和 `SHARED_CONFIGURATION_ID`，实际生效值应核对正在运行的进程；不能只看 `.env.local` 中的历史值。`scripts/run-start.mjs` 负责选择本地模式，`src/storage/database/configuration-source.ts` 负责配置表路由。

要让两个正式管理入口看到同一份已发布提示词，两端必须选择同一个配置身份和数据源。在隔离模式完成的草稿，先按选定正文摘要发布并分别读回；不要为了同步提示词切换全部用户、钱包、历史或媒体数据。

智能体的 `config_revision` 在所属数据源内递增。两个独立数据库的第20版与第14版不能直接比较先后；核对目标数据源、智能体ID、正文SHA-256和该目标的保存版本。编辑时携带读取到的版本，陈旧编辑被拒绝后应刷新合并，不能按客户端时间强行覆盖。

主站智能体保存于 `agents`，历史正文由 `prompt_versions` 记录。独立分镜工作台编译器保存在 `platform_settings`，不属于同一个智能体记录，也未列入现有共享配置表清单；同步主站提示词不能推断编译器一起更新。共享读取更新发生在后续请求，不等于已经打开的所有页面都有实时推送。

## 管理员以后如何添加对话模型

在后台模型资源池选择“添加模型”，选择对话模型，按供应商提供的实际接口填写：

1. 选择接入站点和协议。OpenAI Chat 与 Anthropic Messages 是不同请求合同；同一站点可以支持多个协议，也可能只开放其中一种。
2. 明确选择 Bearer 或 x-api-key。Anthropic 协议另有 API 版本。使用站点模板只会填非敏感默认值，不代表真实通路已验收。
3. “供应商模型 ID”填写接口的精确ID，“展示名称”填写用户看到的名称。以后新增同协议型号不需要改源码；全新协议仍需相应适配器。
4. 填写当前站点的密钥、成本、上下文、最大回复Token和超时。OpenAI可明确选择 `max_tokens` 或 `max_completion_tokens`；Anthropic使用 `max_tokens`。未知能力由管理员按供应商确认值填写，不根据名称自动猜测极限。
5. 思考请求默认采用供应商默认行为。只有明确支持时才选择 Adaptive + Low；不向不支持关闭推理的型号强行发送 disabled。
6. 保存为候选，检查并发布目标候选；发布后在该模型卡执行一次“真实文字验证（付费）”。成功且当前配置的证据有效后，点击“启用当前配置”，再刷新读回。

验证使用服务端保存并发布的配置，不混用编辑中的草稿。草稿诊断不产生可激活证据；改协议、端点、凭据或影响指纹的参数后，需要验证新配置。普通保存不能绕过启用流程。上游失败不会自动隐藏、删除或切换模型。

同站点编辑时密钥留空可保留原值；换到另一站点必须提供新的凭据，不能把旧站点密钥默认发送过去。后台响应不返回原密钥，候选预览不携带明文。

“目录存在”“鉴权目录列出型号”“最小文字调用成功”“业务文案质量达标”“生产已发布”是不同状态。只有相应证据实际完成，才能使用对应结论。
