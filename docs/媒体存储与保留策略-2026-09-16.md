# 媒体存储与保留策略（2026-09-16）

## 结论

当前正式媒体链路以腾讯云 COS 为云端对象存储：稳定生成视频固定写入 `tencent_cos`，视频参考素材与数字人输入素材也明确写入腾讯 COS；对象归属、文件类型和来源保存在产品数据库 `user_files` 中。开发环境仍支持本机 `public/uploads`，但生产环境未明确设置 `ALLOW_LOCAL_STORAGE_IN_PRODUCTION=true` 时禁止使用或回退到本机对象存储，缺少云存储配置会失败关闭。

本机 `.env.local` 当前没有显式指定 `STORAGE_DEFAULT_PROVIDER`，但 COS 凭据与存储桶已配置，现有选择算法会推断默认供应商为 `tencent_cos`。数据库 `platform_settings.storage_default_provider` 的显式值优先级更高，部署验收仍必须通过管理员存储状态接口回读实际 `defaultProvider`、`productionSafe` 和 `issues`，不能只根据环境文件判断线上事实。

浏览器里的“本地副本”由 Cache Storage 保存媒体内容、IndexedDB 保存索引；默认三天由本站清理。即使用户选择“尽量保留”，也只是跳过本站到期清理，浏览器、系统清理工具、磁盘空间回收、退出账号或清站点数据仍可能移除它。它不是电脑文件系统中的永久文件。需要长期保存时，用户必须使用“下载到电脑”，并自行放入稳定目录或备份盘。

## 目标保留期

| 对象类型 | COS key 前缀 | 目标期限 | 说明 |
|---|---|---:|---|
| 生成视频 | `videos/generated/` | 3 天 | 视频制作、分镜视频等稳定成片 |
| 提取视频 | `videos/extracted/` | 3 天 | 链接提取后转存的视频 |
| 数字人长视频和分段 | `videos/digital-human-long/` | 3 天 | 中间分段与最终合成 |
| 漫剧最终视频 | `short-drama/final/` | 3 天 | 最终视频及派生视频 |
| 创作图片、角色与画面素材 | `images/`、`image-workbench/` | 30 天 | 生图、角色、场景、分镜参考图 |
| 视频参考图/参考音频 | `video-inputs/`、`video-audio-inputs/` | 30 天 | 用户提交给视频模型的参考素材 |
| 数字人输入素材 | `digital-human-inputs/` | 30 天 | 人物图、人物视频和驱动音频 |

`audio/generated/`、平台公共素材 `assets/releases/`、业务备份 `business-data/`、管理员上传的站点展示素材不在本轮自动删除范围，避免把尚未批准期限的音频、发布资产或备份误删。

历史、任务、账单元数据继续保留。生命周期到期只清理媒体对象字节，不删除 `video_tasks`、对话、生成记录、支付流水或扣费记录，也不把过期资产伪装成“从未生成”。`user_files.meta` 从本次修改后会记录策略版本、目标期限和 `cos_lifecycle_required`，它是审计目标，不代表腾讯 COS 已执行删除。

## 当前已经实现

- 对象存储管理器按“数据库显式设置 → 环境变量显式设置 → 已配置 COS → 已配置 Coze S3 → 本机开发存储”选择供应商。
- 生产环境默认失败关闭，禁止在 COS 配置失败后静默写进发布机磁盘。
- 稳定视频固定使用 `tencent_cos` 和 `videos/generated/`；参考素材和数字人素材采用独立前缀，便于生命周期隔离。
- 经统一对象存储管理器上传的新对象，会在 `user_files.meta` 写入目标保留规则；浏览器直传仍依靠相同 COS 前缀匹配生命周期。未增加数据库字段或迁移。
- 视频历史与统一媒体历史已移除“永久保存”承诺，明确浏览器缓存可能被回收，并把长期保存操作标为“下载到电脑”。
- 浏览器临时视频副本仍是三天缓存；“尽量保留”只改变站内清理，不对浏览器系统回收作永久承诺。
- `deploy/policies/media-object-retention.v1.json` 已给出部署契约，并明确状态为 `deployment_configuration_required`。

## 尚未证明生效的部署项

源代码和策略模板不会自动修改腾讯云账号。以下动作完成前，不得宣称云端 3 天/30 天自动清理已经生效：

1. 在目标腾讯 COS 存储桶逐前缀创建生命周期规则。每个前缀单独配置，生成/派生视频为 3 天，角色和创作参考素材为 30 天；禁止对整个 `videos/`、`images/` 或存储桶根目录建立宽泛规则。
2. 从 COS 控制台或 API 回读全部规则，核对 Bucket、Region、规则状态、前缀和过期天数，并保存不含密钥的回执。
3. 创建两个不承载业务的验收对象，分别命中 3 天和 30 天前缀；用对象元数据确认规则匹配。不要为了测试删除真实用户资产。
4. 配置服务端每日只读对账：发现 COS 对象已过期时，历史与账单保留，媒体接口返回“云端文件已到期，请使用已下载文件”；不得把任务改成失败、退款或重新提交。
5. 完成规则回读后，在构建环境设置 `NEXT_PUBLIC_MEDIA_RETENTION_ENFORCED=true`。该开关只控制客户提示是否显示明确“三天”，必须后于 COS 规则启用，不能先开。
6. 部署后用普通学员账号零付费验收视频页、媒体历史、下载到电脑、浏览器临时副本说明；再通过管理员状态接口确认 `defaultProvider=tencent_cos`、`productionSafe=true`、`issues=[]`。

如果将来需要在应用服务内主动删除 COS 对象，应另建带 dry-run、前缀白名单、批次上限、审计回执和可恢复窗口的清理任务。本轮没有加入数据库迁移，也没有加入会在部署后自动删除历史对象的后台任务。

运行：

```powershell
node .\scripts\run-node-maintenance-tsx.mjs .\scripts\verify-media-retention-policy.ts
pnpm verify:media-cache
pnpm verify:media-history-ui
```

三项检查均不发起网络请求、不写产品数据库、不上传或删除 COS 对象，也不调用任何付费模型。
