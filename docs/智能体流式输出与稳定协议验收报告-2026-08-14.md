3. `src/components/chat-view.tsx`、`src/components/chat/message-item.tsx`

4. `src/lib/conversation-cache.ts`
   - 可缓存流式中的部分正文，但恢复时丢弃了 `interrupted` 的可见状态，用户无法判断是否需要续写。

## 2. 根因

1. SSE 解析分散在三套函数中，未统一处理 UTF-8 字符边界、多行 data、事件 ID 去重。
2. 流式正文与结构化结果没有事务边界，缺少“流结束后一次校验、一次映射”的协议层。
3. 卡片映射依赖标题和代码框顺序，提示词改标题或改顺序就可能错配。
4. 中断内容虽然保留，但没有续写入口；刷新恢复后也没有中断标识。
5. 机器 JSON 默认完整铺开，挤压人类可读的两个 Prompt 代码框。

## 3. 已完成改造

### 3.1 SSE 增量解码

新增 `src/lib/sse-stream-decoder.ts`：

- 使用流式 `TextDecoder` 保留被拆开的中文 UTF-8 字节；
- 支持 CRLF、LF、多行 `data:`、`event:`、`id:`、`retry:`；
- 服务器提供事件 ID 时对重连重放做幂等去重；
- 提供续写重叠合并，避免模型从中断句尾重复输出。

三套聊天 SSE 消费路径已统一接入该解码器，未修改任何 API 服务端代理。

### 3.2 稳定协议与 DTO

新增 `src/lib/structured-agent-output.ts`。解析优先级：

1. 严格识别 `storyboard_director_output.v1`；
2. 严格识别 `agent_prompt_package.v1`；
3. 兼容旧 `frame_count` 机器包；
4. 最后才兼容旧版每段两个 `text` 代码框。

稳定协议不会按标题、代码框顺序或自然语言关键词猜字段。未来工作台 DTO 固定为：

```text
segment_id
narration
image_prompt
video_prompt
panel_count
layout
pacing_mode
actual_shot_count
panoramic_anchor_role
```

只有流结束、schema 和字段全部校验通过后，才发布一次 `agent-structured-output-ready` 事件，并把最新 DTO 写入会话级缓存。重复渲染、重复 SSE 事件或同一消息重复提交不会重复插卡。

### 3.3 聊天展示与恢复

- 每段原有两个独立 `text` 代码框保持不变，可分别一键复制；
- 识别出的机器 JSON 从正文中移出，默认折叠，但可以检查和复制；
- 机器 JSON 未闭合或格式错误时保留全部可读正文，并显示“重试解析”；
- 停止、断网或异常中断后保留已收到内容，显示“继续生成”；
- 继续生成不删除旧正文，使用专门续写指令要求只补缺失部分，并在末尾给出一个完整机器包；
- 浏览器崩溃后从本地缓存恢复的流式消息会保留中断提示。

### 3.4 映射兼容

- 消息动作栏推送视频时，优先从稳定 DTO 的 `video_prompt` 映射；
- 非结构化普通聊天仍保留原有兼容入口；
- 本阶段只发布 DTO 和兼容事件，未修改 `storyboard-workbench` 页面或样式。

## 7. 回归风险

2. 旧双代码框没有机器字段，`pacing_mode`、`actual_shot_count` 等只能使用兼容默认值；UI 会明确标注“旧版兼容”。
